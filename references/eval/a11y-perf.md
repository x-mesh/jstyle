# 접근성(L7)과 성능(L8)

## L7 — 페이지마다 axe-core

페이지가 자리 잡은 뒤(네트워크가 잠잠하거나 1.5초 정도) 1440에서 [axe-run.js](../../scripts/eval/axe-run.js)를 한 번 실행합니다.
375 휴대폰 흉내에서 시작 페이지와 틀마다 한 곳을 다시 봅니다. 햄버거 버튼, 휴대폰 메뉴, 고정 막대는 거기에만 있습니다.
넓은 화면 결과와 합치고 규칙은 한 번만 적습니다.
대화상자나 서랍이 열리면 ARIA가 바뀌니 다시 실행합니다. 어두운 모드가 있으면 그 모드에서도 한 번 봅니다. 대비는 그쪽에서만 실패하기도 합니다.

| axe `impact` | 심각도 | 차단 조건 |
|---|---|---|
| critical | Critical | 예 |
| serious | High | 예 |
| moderate | Medium | 아니요 |
| minor | Low | 아니요 |

사이트 전체에서 규칙과 컴포넌트로 묶습니다. 규칙 하나·컴포넌트 하나(같은 `target` 선택자나 같은 마크업)에 발견 하나이며 영향받는 페이지와 전체 노드 수를 적습니다.
25쪽에서 `color-contrast`에 걸린 공통 머리글도 발견 하나입니다.

```text
### F-05 · 대비가 낮은 보조 버튼
심각도: High · 층: L7 접근성 · 종류: 고침값 · 확신도: 측정
위치: /, /pricing, /features의 .btn-secondary (노드 7개)
원칙: WCAG 1.4.3 Contrast (AA)
근거: axe color-contrast (serious) · <button class="btn-secondary">더 알아보기</button>
관찰: 3.2:1   기대: 4.5:1 이상
고침: --muted-foreground oklch(0.55 0 0) → oklch(0.45 0 0)
```

### 사람이 봐야 할 것(`incomplete`)

axe가 정하지 못하면 `incomplete`를 돌려줍니다. 대개 이미지·그라디언트·겹친 요소 위의 `color-contrast`입니다.
바로 대비가 실제로 잘 실패하는 대표 배너와 카드입니다.
`incomplete` 규칙마다 캡처를 보고 되면 가장 나쁜 곳을 잰 뒤 발견(`관찰`)으로 올리거나 확인 범위에 "봤고 괜찮음"을 적습니다.
확인하지 않은 `incomplete`는 차단 조건에 세지 않습니다.

### `target-size`

axe `target-size` 결과는 L6이 주인입니다. [반응형](responsive.md#클릭-대상l6이-주인)의 클릭 대상 발견에 합칩니다.

### 불러오지 못했을 때

페이지의 CSP나 네트워크가 CDN 스크립트를 막으면 `axe-run.js`는 `error`를 돌려줍니다.
`axe: 막힘(CSP)`처럼 적고 아래 직접 확인으로 바꾸며 L7은 `일부`입니다.

### axe가 놓치는 것 — 키보드로 직접 확인

시작 페이지와 모든 전환 페이지에서 합니다.

- 모든 것을 Tab으로 지나갑니다. 초점이 늘 보이고 순서가 읽는 순서를 따릅니다.
- 내용이 많은 페이지에 본문 바로가기 링크가 있습니다.
- Escape로 대화상자와 메뉴를 닫고 초점이 연 버튼으로 돌아갑니다.
- 키보드가 갇히지 않습니다.
- 올려야 열리는 메뉴가 초점으로도 열립니다.
- 폼 오류를 색만이 아니라 글로 알립니다.
- 뜻이 있는 `<img>`는 뜻 있는 alt, 꾸밈 이미지는 `alt=""`입니다.
- 제목 단계를 건너뛰지 않고 `h1`이 하나입니다.
- `prefers-reduced-motion`: 큰 움직임이 멈추거나 약해집니다.

금융·의료·법률·공공처럼 위험이 큰 분야는 모든 페이지에서 키보드 확인을 합니다.
`jstyle eval --keyboard`가 Tab 순서, 초점 표시, 화면 밖 초점, 본문 바로가기, 갇힘의 단서를 남깁니다.
초점 표시 단서는 켰을 때와 껐을 때 스타일이 같다는 뜻일 뿐이므로 `<페이지>-focus-<번호>.png`로 확인한 뒤 발견으로 올립니다. 가상 요소(`::after`)로 그린 표시는 잡지 못합니다.
Escape, 올려야 열리는 메뉴, 폼 오류 알림은 환경의 브라우저 도구로 하고, 못 하면 확인 범위에 적습니다.

## L8 — 성능

시작 페이지와, 있다면 주된 전환 페이지를 잽니다.

[perf-capture.js](../../scripts/eval/perf-capture.js)를 두 번 실행합니다. 열린 직후 한 번(LCP, CLS, TTFB), 실제 조작 하나 뒤 한 번(INP)입니다.
그 조작은 페이지를 떠나거나 무언가를 제출하면 안 됩니다.

- 보기만 하는 범위: 메뉴, 접이식, 탭, 가격 전환 열기
- 사용자 사이트: 주된 동작도 괜찮습니다

안전한 조작이 없으면 INP를 `n/a (안전한 조작 없음)`으로 적습니다.
`jstyle eval`은 조작하지 않으므로 INP는 대개 `no interaction`이며, 필요하면 다른 도구로 한 번 눌러 다시 잽니다.

`perf-capture.js`의 `inpStatus`:

| `inpStatus` | 적는 법 |
|---|---|
| `measured` | `INP <inpMs> ms`를 기준과 비교 |
| `fast (< 16 ms)` | `INP < 16 ms`. 브라우저는 더 느린 사건만 알려 주며 모든 기준을 통과합니다 |
| `first input only` | `INP ≈ <inpMs> ms (첫 입력)`. 사건 기록이 없어 첫 입력 시간으로 대신하며 기준과 비교합니다 |
| `no interaction` | 조작이 페이지에 닿지 않았습니다(다른 요소, 만든 이벤트). 다시 시도하고 아니면 `n/a` |

| 지표 | 일반(앱·콘텐츠) | 전환(랜딩·가격·가입·결제) | 넘으면 |
|---|---|---|---|
| LCP | 4.0초 미만 | 2.5초 미만 | High(차단 조건) |
| CLS | 0.25 미만 | 0.1 미만 | High(차단 조건) |
| INP | 500ms 미만 | 200ms 미만 | High(차단 조건) |
| TTFB | 1.8초 미만 | 0.8초 미만 | Medium |

정의는 web-vitals를 따릅니다. TTFB는 탐색 시작부터 셉니다(리디렉션·DNS·연결 포함).
CLS는 모든 밀림의 합이 아니라 가장 큰 5초 묶음입니다.

브라우저 없는 실행은 속도 제한이 없어 낙관적입니다. 조건을 보고서에 적습니다.
제한 없이 잰 LCP가 기준의 60%를 넘으면(예: 4.0초 기준에 2.5초) 실제 휴대폰 4G에서는 넘을 수 있습니다.
Medium, 확신도 `판단`으로 올리고 도구가 되면 네트워크·CPU 제한을 걸어 다시 잽니다. 제한을 건 측정에서 넘으면 차단 조건입니다.
한 지표라도 넘으면 다른 주요 경로도 잽니다.

| 증상 | 흔한 원인 |
|---|---|
| LCP 높음 | 최적화하지 않은 대표 이미지, 큰 JS 묶음, 그리기를 막는 글꼴·CSS. `lcpElement`를 봅니다 |
| CLS 높음 | 늦은 글꼴 바뀜, 자리를 잡지 않은 임베드·광고, 첫 화면 위의 클라이언트 렌더링 |
| INP 높음 | 무거운 클릭 처리, 입력마다 다시 그리기, 동기 JSON 처리, hydration |
| TTFB 높음 | CDN 캐시 없음, 느린 서버 렌더링, 리디렉션 사슬 |

네트워크 목록에서 전체 전송량, 이미지 형식(WebP/AVIF?), 압축하지 않은 자료, 요청 수도 적습니다.
