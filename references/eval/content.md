# 내용·구조·전환·기술 점검(L1, L2, L3, L5)

화면을 그려야 알 수 있는 항목(첫 화면, 페이지 안의 차례, 첫 화면 경계)은 ◐로 표시합니다.
글만 받아 볼 때는 건너뛰고 해당 층을 `일부`로 적습니다.
페이지마다 보는 항목을 먼저 하고, 다 읽은 뒤 페이지 사이 비교를 한 번 합니다.

## L1 — 문구와 내용

남은 임시 글

- 라틴 채움 글, "TODO", "TBD", "제목을 입력하세요", 테마 기본 문구, 예시 후기 → 차단 조건
- 0에 멈춘 숫자, 빈 통계 칸, "홍길동" 같은 기본 아바타
- 날짜나 설명 없는 "준비 중" 구역

정확함

- 맞춤법·띄어쓰기·문장 부호
- 한 가지 지역 표기([원칙과 언어](principles.md#언어별-점검))
- 제품 이름·가격·날짜·법인 이름이 어디서나 같음

알맹이

- 경쟁사가 이 제목을 그대로 가져가도 말이 되면 아무것도 말하지 않은 것입니다.
- 만든 사람의 기능 목록이 아니라 읽는 사람의 이득으로 말합니다.
- 제목이 약속한 것을 아래 구역이 주지 않는 곳
- 제목만 있고 내용이 없거나 목적이 분명하지 않은 구역

페이지 사이

- 말투 차이(한 페이지는 편하게, 다른 페이지는 딱딱하게)
- 여러 페이지에 복사해 붙인 같은 문장
- 페이지마다 다른 수치(고객 수, 운영 시간, 가격)
- 한 개념에 여러 이름

## L2 — 구조·이동·과제 흐름

- ◐ 첫 화면(`fold-check.js`): 몇 초 안에 무엇인지, 나를 위한 것인지, 다음에 무엇을 할지 말할 수 있습니까?
- 갈림길: 여러 사용자나 요금제를 상대하면 각자의 길이 분명합니까?
- ◐ 차례: 필요 → 답 → 근거 → 제안 → 안심 → 행동으로 이어지는지, 블록을 쌓아 놓기만 했는지 봅니다.
- 밀도: 한 블록이 세 가지 넘게 말하려는 곳
- 중복: 까닭 없이 한 페이지에 두 번 나온 요소
- 빈틈: 어떻게 동작하는지 설명이 없음, 흔한 질문의 답이 없음, 다음 단계 없이 끝나는 페이지
- 길 찾기: 모든 페이지가 두 번 안에 닿음, 지금 위치가 보임, 긴 페이지에 목차나 고정 메뉴가 있음
- ◐ 작은 화면: 375px에서 글 벽이 되는 문단
- 과제 흐름: [과제 따라가기](walkthrough.md)의 막다른 길, 헷갈리는 이름, 묻힌 답
- 상태: 빈 화면·불러오는 중·오류·성공·404가 있고 다음에 할 일을 알려 줌

## L3 — 전환 경로와 폼

- 버튼 글이 다음에 일어날 일을 말합니다("15분 상담 예약", "제출"이 아님).
- 동작 하나, 이름 하나, 도착지 하나를 어디서나 지킵니다.
- ◐ 주된 버튼이 1440×900과 375×812 첫 화면 안에 있습니다(`fold-check.js`). 고정된 버튼도 칩니다.
- 가격을 찾아 헤매지 않고, 숫자의 맥락(비교 요금제, 월별 금액, 포함 범위)이 있습니다.
- ◐ 후기·로고·사례 수치가 요청 앞에 있고 믿을 만큼 구체적입니다.
- 남은 수량·카운트다운이 진짜입니다. 가짜 긴급함은 믿음의 Critical입니다.
- 환불 조건·보증·보안·연락처가 결제나 가입 가까이에 보입니다.
- 사용자의 큰 걱정에 별도 도움말이 아니라 페이지에서 답합니다.
- 아직 준비되지 않은 사람을 위한 가벼운 선택(데모, 뉴스레터, 무료 자료)이 있습니다.
- 폼은 지금 필요한 것만 묻습니다.

### 폼(읽기만, 모든 범위)

폼이 있는 페이지마다 [form-audit.js](../../scripts/eval/form-audit.js)를 실행합니다. 아무것도 입력하거나 제출하지 않습니다.

| 확인 | 스크립트 필드 | 심각도 |
|------|---------------|--------|
| 모든 입력에 프로그램이 읽는 이름표가 있음 | `unlabeled` | 전환 폼은 High. axe가 잡으면 WCAG 1.3.1 / 4.1.2로 L7 |
| 자리표시 글만 이름표로 쓰지 않음 | `placeholderOnly` | Medium. 입력하면 안내가 사라집니다(H6) |
| 이메일·전화·숫자에 맞는 입력 종류 | `typeMismatch` | Medium. 휴대폰 자판이 틀립니다 |
| 이름·이메일·주소·전화·카드에 `autocomplete` | `missingAutocomplete` | Low~Medium. 다시 쳐야 합니다(H7) |
| 필수 항목을 제출 전부터 표시 | `requiredUnmarked` | Medium |
| 제출 버튼이 일어날 일을 말함 | `genericSubmit` | 전환 폼은 Medium |
| 입력 수가 약속의 무게에 맞음 | `fieldCount` | 판단. 뉴스레터에 6칸이면 발견입니다 |

## L5 — 기술과 검색 노출

| 확인 | 방법 |
|------|------|
| 내부 링크가 열림 | 같은 주소의 `href`를 모아 요청하고 4xx·5xx를 적습니다 → 차단 조건 |
| 같은 글 → 같은 도착지 | 링크를 글로 묶고 도착지가 여럿인 묶음을 적습니다 |
| 닿을 수 있음 | `sitemap.xml`에 있지만 어느 메뉴도 가리키지 않는 주소 |
| 되풀이된 블록 | 같은 `innerText` 블록이 두 번(화면 읽기 도구에 드러나는 숨은 반응형 사본도 칩니다) |
| `<title>` | 있고, 페이지마다 다르고, 대략 60자 이하 |
| meta description | 있고, 다르고, 대략 160자 이하 |
| 이미지 | 정보 이미지에 뜻 있는 `alt`, 꾸밈 이미지에 `alt=""`, 그림과 맞는 설명 |
| 주소 | 읽기 쉬운 경로, 오타나 이상한 인코딩 없음 |
| 공유 미리보기 | `og:title`, `og:description`, 열리는 절대 주소 `og:image` |
| 색인 | 알맞은 canonical, 실수로 넣은 `noindex` 없음, `robots.txt`가 공개 페이지를 막지 않음 |
| 언어 | `<html lang>`이 내용과 맞음 |
| 기본 | 파비콘이 열림, 404 화면에 돌아갈 길, `https://` 페이지에 `http://` 자료 없음 |

`jstyle eval`의 `head` 결과에 제목·설명·canonical·robots·lang·og·h1·`alt` 없는 이미지가 있습니다.
다른 도구에서는 다음 식을 실행합니다.

```js
(() => ({
  title: document.title,
  description: document.querySelector('meta[name="description"]')?.content ?? null,
  canonical: document.querySelector('link[rel="canonical"]')?.href ?? null,
  robots: document.querySelector('meta[name="robots"]')?.content ?? null,
  lang: document.documentElement.lang || null,
  og: Object.fromEntries([...document.querySelectorAll('meta[property^="og:"]')].map(m => [m.getAttribute('property'), m.content])),
  h1: [...document.querySelectorAll('h1')].map(h => h.innerText.trim()),
  imgsMissingAlt: [...document.querySelectorAll('img')].filter(i => !i.hasAttribute('alt')).map(i => i.currentSrc || i.src).slice(0, 20),
}))()
```

## 목록이 많은 사이트(상품, 강의, 사람)

- 모든 상세 페이지가 다 채워져 있고 반만 쓴 항목이 없습니다.
- 목록 카드가 한 형식을 씁니다.
- 분류·단계·태그가 정확합니다.
- 사람 소개가 이름·역할·짧은 소개·사진을 같은 식으로 갖춥니다.
