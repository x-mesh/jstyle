# 조작과 동작(L9, `app` 모드)

사용자가 소유했거나 점검을 허락받은 사이트에서만 합니다. 남의 사이트에서는 이 층을 `보지 않음(보기만 하는 범위)`으로 적습니다.
코드를 읽으면 버튼에 처리기가 있다는 것만 압니다. 눌러 봐야 동작하는지 압니다.
앞 단계에서 본 상태를 다음 단계에 쓸 수 있도록 같은 세션에서 이어서 합니다.

이 층은 디자인 평가가 보는 범위까지만 다룹니다. 화면이 실제 작업을 끝내게 하는지, 실패를 숨기지 않는지 봅니다.
깊은 기능 검사나 자동 테스트 작성은 프로젝트의 테스트 도구로 넘깁니다.
위험한 경로를 고르는 법은 [살펴보고 고치기](../extended/review-loop.md#위험을-겨냥한-확인)와 같습니다.

## 과제

[과제 따라가기](walkthrough.md)에서 고른 3~5개를 이번에는 끝까지 합니다. 입력하고, 제출하고, 결과를 확인합니다.
상태가 바뀔 때마다 찍습니다. 대기 → 올림·초점 → 누른 뒤 → 불러옴 → 확인됨.
멈칫한 곳, 막다른 길, 더 누른 곳은 모두 발견이며 [원칙과 언어](principles.md)의 원칙을 붙입니다.

## 조작 기록(필수)

```text
조작 기록 — /app/clients
  사용자: 통화 사이에 짬을 내는 영업 담당, 인내심 낮음
  [✓] 14:32:01 검색창(input[name="q"])에 "Zoë O'Brien" 입력
  [✓] 14:32:04 "고객 추가"(button[data-testid="add-client"]) 누름
  [✓] 14:32:06 대화상자 열림(role=dialog 보임)
  [✓] 14:32:11 제출 → 알림 "저장됨", 목록 12 → 13
  [✓] 14:32:12 콘솔: 자체 오류 0, 경고 0
  [✓] 캡처: clients-before.png, clients-after.png
  [✓] 네트워크: POST /api/clients 201, 5xx 없음
```

페이지마다 적어도 실제 글 입력 하나, 주된 동작 하나, 대화상자나 상세 보기 하나, 동작 뒤 콘솔 읽기, 전후 캡처, 기대한 결과가 일어났는지 확인을 남깁니다.
모든 줄은 그때 실제로 한 도구 호출과 맞아야 합니다. 빠지면 판정은 `확인 부족`입니다.
저장은 [마치기](../../SKILL.md#마치기)처럼 다시 읽고 새로고침해 확인합니다.

## 조용한 실패 찾기

컨트롤마다 누른 뒤 네트워크(요청이 맞는 곳으로 나갔나)와 DOM(눈에 보이게 바뀌었나)을 봅니다. 둘 다 아니면 버그입니다.
흔한 곳: 아무것도 연결하지 않은 버튼, 대화상자 안에서 막힌 팝업, 끝나지 않는 검증, 몰래 되돌아가는 낙관적 갱신, 하나 어긋난 페이지 넘김, 다시 불러오지 않는 필터.

## 처음 온 사람

여러 단계 기능마다 문서 없이 처음 왔다고 생각합니다.

- 바깥 도움 없이 끝낼 수 있나?
- 이름표가 내부 식별자가 아닌 쉬운 말인가?
- 선택 목록이 각 선택을 설명하나?
- 기본값을 받아들이고 넘어갈 수 있나?
- 입력이 필요할 때 무엇이 맞는지 알 수 있나?

처음 온 사람에게 "그건 그냥 넘기세요"라고 말하고 싶다면 그 화면에 발견이 있습니다.

## 시나리오

해당하는 것만 하고 나머지는 까닭과 함께 `n/a`로 적습니다.

1. 맨 처음: 아무 맥락 없이 시작해 2분 뒤 각 과제를 설명할 수 있나?
2. 끊김: 폼 도중 새로고침·탭 닫기·이동. 작업이 남거나 분명히 경고하나?
3. 잘못 든 길: 일부러 틀린 길로 갑니다. 돌아오는 비용은?
4. 두 번째 방문: 과제를 되풀이합니다. 더 빠르고 바뀐 것이 보이나?
5. 키보드만: 초점 보임, 알맞은 순서, Escape로 닫힘, 갇힘 없음. 발견은 L7입니다.
6. 양: 목록 0개·1개·많이·아주 많이. 빈 화면, 페이지 넘김, 검색, 필터.
7. 되돌릴 수 없는 동작: 삭제·공개·보내기. 분명한 확인, 구체적인 말, 되돌리기. 실행 전에 묻습니다.
8. 다른 역할: 읽기 전용이나 제한된 사용자가 알맞은 화면과 분명한 권한 안내를 봅니다. 화면에서 숨긴 것만으로 통과하지 않습니다.
9. 왕복: B에서 바꾸고 새로고침 없이 A로 돌아갑니다. A에 반영됐나?
10. 까다로운 입력: 아포스트로피, 악센트, 한중일 글자, 오른쪽에서 왼쪽 글, 이모지, 아주 긴 값, 글로 친 HTML 태그(그대로 보여야 함). 몰래 지우거나 자르면 발견입니다.
11. 나쁜 네트워크: 느림과 끊김에서 불러오는 상태, 다시 시도, 저장 안 한 변경 경고.

## 로그인이 끊겼을 때

전에 되던 경로에서 401·403이 나오면 세션이 끊긴 것입니다. 말없이 다시 로그인하지 않습니다. 그 뒤의 관찰은 믿을 수 없습니다.
단계를 적고(조용한 만료 자체가 발견입니다) 멈춘 뒤 `확인 부족`으로 표시합니다.
