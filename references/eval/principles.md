# 원칙과 언어

발견에는 어긴 원칙을 붙입니다. 무엇이 어긋났는지뿐 아니라 왜 해로운지 사이트 주인이 알 수 있습니다.
발견에는 짧은 기호를 씁니다. 예: `원칙: H4 일관성 — "시작하기"가 두 가지 뜻으로 쓰임`.

## Nielsen의 사용성 원칙 열 가지

| 기호 | 원칙 | 웹에서 흔한 증상 | 흔한 층 |
|------|------|------------------|---------|
| H1 | 시스템 상태의 가시성 | 불러오는 표시 없음, 제출 뒤 확인 없음, 현재 메뉴 표시 없음, 주된 버튼이 안 보임 | L4, L9, L3 |
| H2 | 실제 세계와 맞음 | 내부 용어, 읽는 사람의 결과가 아닌 만든 사람의 기능 이름 | L1, L9 |
| H3 | 사용자의 통제와 자유 | 뒤로·되돌리기 없음, 닫을 수 없는 대화상자, 뒤로 못 가는 단계 화면 | L9, L2 |
| H4 | 일관성과 표준 | 같은 글 → 다른 곳, 버튼 스타일 5종, 글처럼 보이는 링크 | L3, L4 |
| H5 | 오류 예방 | 확인 없는 삭제, 고르기가 맞는 곳의 자유 입력, 입력 제한 없음 | L3, L9 |
| H6 | 기억보다 알아보기 | 3단계에 필요한 정보가 1단계에만 있음, 이름 없는 아이콘 버튼 | L2, L4 |
| H7 | 유연함과 효율 | 큰 목록에 검색 없음, 키보드 경로 없음, 같은 자료 다시 입력 | L9, L7 |
| H8 | 미적이고 간결한 디자인 | 겨루는 주된 버튼 셋, 글 벽, 말을 덮는 장식 | L4, L2 |
| H9 | 오류를 알아보고 회복 돕기 | "문제가 발생했습니다", 색만으로 표시한 오류, 입력과 멀리 떨어진 오류 | L3, L9, L7 |
| H10 | 도움과 문서 | 흔한 걱정에 페이지에서 답하지 않음, 따로 숨은 도움말 | L3, L2 |

## 함께 쓰는 법칙

| 기호 | 법칙 | 쓰는 때 |
|------|------|---------|
| FITTS | 대상이 멀고 작을수록 누르는 데 오래 걸립니다 | 작거나 먼 주된 동작, 특히 터치 |
| HICK | 선택지가 많을수록 결정이 늦어집니다 | 10개 넘는 메뉴, 요금제가 너무 많음 |
| JAKOB | 사람들은 이미 아는 사이트처럼 동작하길 기대합니다 | 메뉴·장바구니·검색·로고 링크의 낯선 위치 |
| GESTALT | 가까움·닮음·같은 영역이 묶음을 정합니다 | 엉뚱한 입력에 더 가까운 이름표, 흩어진 관련 항목 |
| FOLD | 첫 화면에 없는 것은 자주 보이지 않습니다 | 첫 화면 높이 아래의 주된 약속이나 버튼 |
| F-PATTERN | 사람들은 왼쪽 끝과 줄의 첫 낱말을 훑습니다 | 문장 가운데 묻힌 핵심 낱말, 오른쪽 정렬한 중요 정보 |

## WCAG

접근성 발견에는 성공 기준을 적습니다. 예: `WCAG 1.4.3 Contrast (AA)`, `WCAG 2.5.8 Target Size (AA)`, `WCAG 2.4.7 Focus Visible`.
axe 결과의 태그와 도움말 주소에 기준이 들어 있습니다.

## 규칙

맞는 원칙이 없으면 대개 취향입니다. 확신도 `판단`(Medium까지)으로만 남기거나 버립니다.

## 언어별 점검

사이트가 겨냥한 표기를 고르고(분명하지 않으면 묻습니다) 벗어난 곳을 모두 적습니다.
표기가 섞이면 규칙을 말하지 못하는 사람에게도 허술해 보입니다.

### 어느 언어에나

- 철자와 낱말의 지역 표기 하나
- 읽는 사람을 대하는 높임 하나
- 숫자·화폐·날짜·시간 표기 하나
- 따옴표와 말줄임표 모양 하나
- 제목과 버튼의 대소문자 규칙 하나
- 기계 번역 흔적: 직역한 관용구, 어색한 어순, 한 곳에서는 번역하고 다른 곳에서는 그대로 둔 용어

### 영어

| 영역 | en-US | en-GB / en-AU |
|------|-------|---------------|
| -or / -our | color, favor | colour, favour |
| -ize / -ise | organize | organise(GB는 둘 다 쓰며 하나를 고릅니다) |
| -er / -re | center | centre |
| 날짜 | 11/08/2026 = 11월 8일 | 11/08/2026 = 8월 11일. "8 November 2026"처럼 헷갈리지 않게 씁니다 |
| 제목 | Title Case가 흔함 | Sentence case가 흔함 |

### 한국어(ko-KR)

| 영역 | 볼 것 |
|------|-------|
| 띄어쓰기 | 의존 명사(수, 것, 때), 보조 용언, 단위 |
| 높임 | 합니다체·해요체·반말을 페이지 사이나 한 흐름 안에서 섞지 않음 |
| 버튼 말 | 명사형("시작하기")이나 권유형("시작해 보세요") 중 하나 |
| 외래어 | 낱말마다 한 표기(콘텐츠/컨텐츠, 메시지/메세지) |
| 번역투 | "~에 대해", "~를 통해", "~하는 것이 가능합니다", 지나친 피동 |
| 줄바꿈 | 낱말 중간에서 끊기는 제목. `word-break: keep-all`이 필요합니다 |

### 언어 더하기

같은 모양으로 절을 더합니다. 지역 표기, 높임 체계, 숫자·날짜 관례, 원어민 편집자가 자주 잡는 실수 다섯 가지.
점검하는 사람이 실제로 확인할 수 있는 것만 둡니다.
