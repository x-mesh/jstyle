# 시각 디자인(L4)

답할 질문은 하나입니다. 디자인을 아는 사람이 "잘 만들었다"고 할까, "개발자가 디자인했다"고 할까.
1440×900과 375×812의 첫 화면·전체 캡처로 판단하고, 어두운 모드가 있으면 둘 다 봅니다.

캡처는 무언가 어색하다는 것을 보여 주지만 16px와 20px를 믿을 만하게 가르지 못합니다.
시작 페이지와 틀마다 한 곳에서 [style-audit.js](../../scripts/eval/style-audit.js)를 실행하고 일관성 발견에는 그 개수를 붙입니다(확신도 `측정`).
캡처만으로 본 발견은 결함이 분명하면(겹침, 보이지 않는 글) `관찰`, 취향이면 `판단`입니다.

대비와 초점 보임은 L7에 적습니다([층의 주인](site-eval.md#층의-주인)).
기존 제품이라면 [화면 살펴보기 안내](../reviewer-manual.md#기존-화면-다듬기)처럼 이상적인 새 스타일이 아니라 사이트 자신의 규칙과 비교합니다.
평가에서는 디자인 1~10점을 내지 않습니다.

먼저 눈을 가늘게 뜨고 캡처를 봅니다. 가장 중요한 요소 하나가 여전히 튀어야 합니다.
"뭔가 이상하다"는 대개 간격 문제입니다. 바깥 여백과 안쪽 여백부터 봅니다.

## 배치와 간격

| 확인 | 좋음 | 나쁨 |
|------|------|------|
| 간격 통일 | 카드 사이, 구역 여백이 같음 | 여기는 16px, 저기는 24px |
| 맞춤 | 구역 사이 왼쪽 시작점이 맞음 | 제목·본문·카드가 서로 다른 세 들여쓰기 |
| 숨 쉴 곳 | 넉넉한 여백 | 상자 끝에 붙은 글, 빽빽한 버튼 |
| 격자 | 분명한 열 격자 | 아무 데나 놓은 요소 |
| 세로 리듬 | 4/8px 척도(8/16/24/32) | 13px, 27px 같은 제멋대로 값. `spacing.offScaleShare`가 높음 |

## 글자

| 확인 | 좋음 | 나쁨 |
|------|------|------|
| 층위 | h1 → h2 → h3 → 본문 차이가 분명 | 제목과 본문이 비슷함 |
| 줄 길이 | 50~75자(한중일 글자는 35~45자 정도) | 한 줄 150자 이상 |
| 줄 간격 | 본문 1.5~1.7(한중일 본문 1.6~1.8), 제목 1.1~1.3 | 빽빽하거나 떠 있음 |
| 크기 척도 | 일정한 척도(14/16/20/24/32), `fontSizes` 8개 정도 이하 | 15, 17, 22처럼 관계없는 값, 12개 이상 |
| 글꼴 | 1~2종(`fontFamilies`) | 3종 이상, 웹 글꼴을 못 받아 대체 글꼴이 보임 |
| 굵기 | 본문 보통, 이름표 중간, 제목 조금 굵게 | 전부 굵게 |
| 줄임 | 말줄임표와 올렸을 때 전체 글 | 말줄임표 없이 잘림(상자 밖으로 나간 글은 L6) |
| 한국어 줄바꿈 | 한국어 제목에 `word-break: keep-all`, 홀로 남은 글자 없음 | 낱말이 두 줄로 쪼개짐 |

## 색

| 확인 | 좋음 | 나쁨 |
|------|------|------|
| 뜻 | 주색 = 동작, 어디서나 | 파랑이 여기는 "누르기", 저기는 "안내" |
| 상태 색 | 성공 초록, 주의 주황, 오류 빨강을 한결같이 | 초록이 성공과 "활성" 둘 다 |
| 색 수 | 2~3색과 무채색 | 층위 없는 무지개 |
| 어두운 모드 | 테두리와 면이 정해져 있고 이미지를 누그러뜨림 | 카드가 배경에 녹음, 눈부신 이미지(읽을 수 없는 글은 어두운 모드에서 axe, L7) |
| 회색 | 한 무채색 계열 | 거의 같은 회색 여럿(`colors.nearDuplicates`) |

## 층위

| 확인 | 좋음 | 나쁨 |
|------|------|------|
| 주된 동작 | 화면마다 두드러진 버튼 하나 | 같은 무게로 겨루는 버튼 셋 |
| 단계적 공개 | 핵심 먼저, 자세한 것은 필요할 때 | 모든 것을 한꺼번에 |
| 묶음 | 관련 항목을 가까이·같은 면에 | 흩어진 관련 항목 |
| 빈 공간 | 의도한 틀 | 갇히고 고르지 않은 여백 |

## 컴포넌트 일관성

| 확인 | 좋음 | 나쁨 |
|------|------|------|
| 버튼 | 주·보조·위험 스타일 하나씩. `controls.buttonHeights` 1~3개(버튼처럼 꾸민 링크 포함) | 버튼 스타일 5종, 한 줄 안의 다른 높이 |
| 카드 | 같은 모서리·그림자·여백 | 섞임 |
| 입력 | 같은 높이와 테두리(`controls.inputHeights`) | 섞인 높이와 테두리 |
| 아이콘 | 한 계열, 한 크기, 한 선 굵기 | 채운 것과 선만 있는 것이 섞임 |
| 모서리 | 척도(입력 4 / 카드 8 / 대화상자 12), 안쪽 모서리 = 바깥 − 여백 | 3/7/10/16px 제멋대로(`radii`) |
| 그림자 | 한두 단계, 한 빛 방향 | 컴포넌트마다 다름(`shadows`) |
| 이미지 | 사진·그림이 한 브랜드처럼 보임 | 스타일이 섞인 스톡 |

## 상호작용 상태

4단계에서 주된 버튼과 메뉴 하나에 올려 두고 Tab으로 첫 컨트롤을 찍은 자료로 봅니다.
터치 흉내에는 올려 두기가 없습니다. 중요한 것이 올려야만 보이지 않는지 확인합니다.

| 확인 | 좋음 | 나쁨 |
|------|------|------|
| 올려 두기 | 누를 수 있는 것이 바뀜 | 반응 없음 |
| 현재 위치 | 지금 메뉴가 표시됨 | 현재와 나머지가 같아 보임 |
| 전환 | 150~200ms ease | 없음(덜컥) 또는 400ms 넘음(굼뜸) |
| 불러오기 | 자리를 잡아 둔 뼈대나 표시 | 내용이 튀어나오며 배치가 밀림 |
| 쓸 수 없음 | 흐리고 `cursor: not-allowed` | 누를 수 있어 보임 |

## 마감 살피기(`app` 모드나 "고급"을 내세우는 사이트)

만든 제품과 찍어 낸 템플릿을 가르는 작은 부분입니다.
버튼 속 아이콘의 눈대중 가운데, 겹친 모서리 규칙, 척도 밖 간격, 거의 같은 회색, 테두리 굵기 차이,
그림자 방향 차이, 어색한 움직임 시간, 너무 세거나 약한 올려 두기 변화, 자간 없는 대문자, 편집 리듬이 나을 곳의 딱딱한 대칭.
[화면 살펴보기 안내](../reviewer-manual.md#더-다듬을-곳)의 마감 항목도 함께 볼 수 있습니다.

## 심각도

[심각도](site-eval.md#심각도)의 영향 × 범위 × 지속을 씁니다. 취향만 있는 발견(`판단`)은 Medium까지입니다.

| 등급 | 예 |
|------|----|
| High | 깨진 대표 이미지, 전환 페이지에서 카드와 구역 경계를 잃은 어두운 모드, 전환 페이지에서 주·보조 버튼을 구분할 수 없음 |
| Medium | 한 줄 안의 다른 버튼 높이, 전체 컴포넌트의 간격 차이, 섞인 아이콘 스타일, 말줄임표 없는 잘림 |
| Low | 1~2px 어긋남, 살짝 다른 모서리, 너무 센 그림자 |

잘 된 것도 늘 적습니다. 고칠 때 지켜야 할 특징입니다.
