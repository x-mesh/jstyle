# 여러 페이지와 설계 규칙

## 페이지 지도

경로, 사용자 작업, 페이지 유형, 핵심 상태, 공유 구성요소를 짧은 목록으로 만듭니다.
목록·상세·편집처럼 구조가 다른 유형마다 대표 화면 하나를 먼저 만듭니다.
대표 화면에서 확인한 탐색, 토큰, 상태를 같은 유형에 적용합니다. 모든 페이지를 동시에 새로 설계하지 않습니다.
다중 에이전트 작업은 별도 허용이 있을 때만 사용하며 공유 파일의 소유자를 정합니다.

## DESIGN.md 작성

실제 만들기에서 확인한 값을 기록합니다. 계획한 값과 만든 값을 섞지 않습니다.
기존 문서가 있으면 필요한 항목만 갱신합니다. 의미가 같은 규칙을 별도 문서에 중복하지 않습니다.
다음 틀에서 해당 항목만 채웁니다. 코드의 위치를 함께 기록합니다.

```markdown
# Design

## 사용자와 핵심 작업

## 보존할 브랜드와 제약

## 토큰
색상 역할, 글자 크기, 간격, 테두리, 모서리, 동작 감소 규칙과 실제 정의 위치.

## 구성요소
공유 컴포넌트 위치, 상태, 입력 방식, 접근성 동작.

## 페이지 유형
경로, 대표 화면, 좁은 화면 전환, 공유 탐색.

## 확인
확인한 화면 크기, 주요 경로, 남은 제약.
```

## 충돌 해결

사용자 결정과 프로젝트의 명시적 규칙을 먼저 적용합니다.
서로 충돌하는 문서의 위치와 실제 코드 차이를 기록합니다. 명확한 우선순위가 있으면 해당 범위만 고칩니다.
브랜드나 공개 계약처럼 임의로 결정할 수 없는 충돌만 사용자에게 묻습니다.
원본 문서를 삭제하거나 전면 통합하는 작업은 별도 요청 없이 수행하지 않습니다.

## 페이지 간 확인

탐색의 현재 위치, 용어, 주 동작 위치, 폼 오류, 날짜와 숫자 형식을 대조합니다.
직접 URL 진입, 새로고침, 뒤로 가기, 저장 후 읽기를 확인합니다.
