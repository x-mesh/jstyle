# 기존 프로젝트에 적용

먼저 요청을 시각 개선, 흐름 고침, 기능 추가 중 하나로 정합니다. 복합 요청이면 해당 범위를 따로 기록합니다.

## 기준선

실제 진입점, 공유 컴포넌트, 토큰, 데이터 소유 위치, 테스트 명령을 확인합니다. 관련 파일만 읽습니다.
대표 화면과 사용자의 핵심 작업 결과를 기록합니다. 오류 고침이면 변경 전에 실패를 재현합니다.
브랜드, 탐색 구조, 저장된 데이터와 공개 인터페이스 중 보존할 항목을 명시합니다.

## 고침 경계

시각 개선은 우연한 스타일만 바꾸고 데이터 흐름과 동작을 유지합니다.
흐름 고침은 막힌 단계와 상태 전이를 고치고 기존 시각 언어를 유지합니다.
기능 추가는 기존 진입점, 권한, 실패 처리와 연결합니다. 시연 버튼만 추가하고 연결됐다고 말하지 않습니다.
여러 화면이 같은 문제를 공유하면 공유 원인을 고칩니다. 한 화면 문제를 위해 전체 토큰을 변경하지 않습니다.

## 고침 요청을 구체화

“고급스럽게” 같은 요청은 실제 화면에서 보이는 원인으로 바꿉니다.
예: 모든 정보의 강조가 같으면 보조 정보의 대비와 크기를 낮추고 주 동작을 유지합니다.
각 고침에서 문제, 변경한 값이나 구조, 유지한 요소, 전후 증거를 남깁니다.
사용자가 선택한 구성을 사소한 취향 때문에 다시 설계하지 않습니다.
문제의 원인이 정보 구조라면 여백과 색상만 바꾸지 말고 구조 변경의 필요성을 설명합니다.

## 완료 조건

같은 경로를 전후에 실행합니다. 저장·읽기·취소와 변경한 상태를 확인합니다.
공유 컴포넌트를 바꾸면 대표 종속 화면도 확인합니다.
무관한 오류와 리팩터링은 고침 범위에 넣지 않습니다.
