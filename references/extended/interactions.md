# 상호작용과 반응형

## 상태 계약

만들기 전에 핵심 동작마다 시작 조건, 진행 상태, 성공 결과, 실패 복구, 취소 결과를 짧게 기록합니다.
비동기 작업에는 idle → pending → success/error 전이가 필요합니다. 중복 제출은 막고 결과는 사용자에게 알립니다.
실패하면 입력과 선택을 유지합니다. 오래된 응답이 최신 선택을 덮어쓰지 않게 요청 식별자나 취소 신호를 사용합니다.
빈 목록, 필터 결과 없음, 권한 없음, 서버 오류는 서로 다른 상태입니다. 각 상태에 유효한 다음 동작을 둡니다.
실제 서비스가 없으면 시연 범위를 문서에 명시합니다. 모의 성공을 실제 저장이나 결제로 보고하지 않습니다.

## 폼

실제 label을 연결합니다. 예시는 placeholder에만 의존하지 않습니다.
필수 여부와 형식을 입력 전에 설명합니다. 첫 입력부터 오류를 표시하지 않습니다.
제출 시 오류 필드로 포커스를 이동하고 오류를 해당 입력에 연결합니다.
서버 확인을 클라이언트 확인으로 대체하지 않습니다. 비밀번호·결제·개인정보를 임의로 브라우저 저장소에 저장하지 않습니다.
저장 성공은 서버 응답 또는 실제 저장소 읽기로 확인합니다. 실패 상태에서도 재시도할 수 있어야 합니다.

## 대화상자와 팝오버

단순한 추가 정보는 인라인 펼침을 사용합니다. 작업 집중이나 위험 확인이 필요하면 대화상자를 사용합니다.
대화상자는 이름, 초기 포커스, 포커스 제한, Escape, 닫은 후 호출 버튼으로 복귀를 확인합니다.
가능하면 확인된 기존 컴포넌트나 native dialog를 사용합니다.
삭제 확인은 대상과 영향을 보여 줍니다. 일반 작업마다 확인창을 추가하지 않습니다.
팝오버는 바깥 클릭과 Escape로 닫히며, 키보드만으로 진입하고 나올 수 있어야 합니다.
메뉴 역할을 선언하면 방향키·Home·End까지 만듭니다. 일반 링크 목록에 불필요한 menu 역할을 붙이지 않습니다.

## 입력과 화면 크기

마우스 hover 없이도 같은 정보를 얻어야 합니다. 터치 타깃은 최소 24×24 CSS px와 충분한 간격을 확보합니다.
키보드 순서를 시각 순서와 맞춥니다. 포커스를 sticky 헤더나 overlay로 가리지 않습니다.
320 CSS px에서 일반 콘텐츠의 가로 넘침을 확인합니다. 표·타임라인은 영역 내부 스크롤과 이름을 제공합니다.
200% 확대에서 주요 작업을 확인합니다. 고정 높이 때문에 문구를 자르지 않습니다.
좁은 화면에서는 탐색을 접고 주 작업을 유지합니다. 필요한 열을 무조건 숨기지 않습니다.
색상만으로 오류·선택·상태를 표현하지 않습니다. 상태 문구와 아이콘을 함께 사용합니다.
시간 제한, 자동 전환, 애니메이션에는 정지 또는 reduced-motion 경로를 제공합니다.
