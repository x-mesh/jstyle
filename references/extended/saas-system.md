# SaaS 스타일 시스템

참고한 B2B SaaS 사이트의 공개 페이지 28곳(홈, 테마 5, 서비스 16, About, 블로그, 가입·문의, 사용 가이드, 보안)을 2026-11-05에 측정해 정리한 규칙입니다.
로그인 뒤 제품 화면은 보지 못했습니다. 제품 UI 규칙은 랜딩 페이지에 실린 제품 목업과 공용 컴포넌트 CSS에서 가져왔습니다.
사이트가 바뀌면 값이 달라질 수 있습니다. 중요한 작업이면 다시 측정합니다.

실행 가능한 예제는 [패턴 라이브러리의 랜딩 연구](../../assets/extended/index.html#landing), 토큰 값은 [landing-tokens.css](../../assets/extended/landing-tokens.css)에 있습니다.

## 쓰는 경우와 경계

- 사용자가 B2B SaaS·HR·업무 도구의 소개 페이지를 어둡고 단정하게 만들 때 씁니다.
- 구조, 비율, 토큰, 상호작용, 문장 톤만 가져옵니다. 참고한 회사의 로고, 심볼, 사진, 일러스트, 제품 스크린샷, 고객사 로고, 마케팅 문구는 복제하지 않습니다.
- 참고한 회사의 제품으로 오인하게 만드는 화면은 만들지 않습니다. 브랜드 이름과 강조색 하나는 프로젝트 고유의 것으로 바꿉니다.
- 프로젝트에 이미 디자인 시스템이 있으면 그 토큰을 우선하고, 이 문서는 배치와 리듬의 참고로만 씁니다.

## 핵심 인상

어두운 바탕(#111)과 흰 글자의 대비, 큰 한국어 제목, 문장마다 한 단어만 칠하는 형광 초록(#0f4), 그리고 흰 섹션 안 회색 틀에 놓인 정갈한 제품 화면이 반복됩니다.
장식은 줄이고 제품 화면 자체를 그림처럼 씁니다. 페이지 사이 차이는 테마 색 하나로만 냅니다.

## 토큰

- 글꼴: Pretendard Variable 하나. 영문 슬로건도 같은 글꼴을 씁니다. 굵기는 400·500·600·700만 씁니다.
- 마케팅 바탕: #111, 더 깊은 구간은 #000. 회색 단계는 흰색 투명도(96·72·48·36·12·8·4%)와 같은 값의 불투명 회색(#262627, #2f2f30, #535354 …)을 짝으로 둡니다.
- 밝은 구간: 흰 바탕 + 블록 #f5f5f7. 글자는 #111의 72·48% 투명도.
- 제품 UI: 잉크 #242a30, 본문 #3e4449, 보조 #61666a, 힌트 #96999c, 비활성 #cacccd, 선 rgb(0 0 0 / .08), 위험 #f24b17, 성공 #09bb1b와 옅은 #e5fae8.
- 강조색 14종(green, lime, yellow, orange, brown, coral, pink, bright pink, lilac, purple, cosmic blue, blue, sky, cyan)은 마커·배지·차트에만 씁니다.
- 테마 색은 주색·보조색·옅은 색 3단계입니다. 에이전트 #288ffe, 구성원 #9169ff, 성장 #c8f832, 정산 #f8cd2d, 비용 #ff6432.
- 글자 크기: 표지 80·64·52, 제목 48·40·36·30·27·24, 부제 22·18·15.5, 본문 17·15·14·13.5·12.5·11.5. 큰 제목은 자간 -2~-3%.
- 간격: 7·11·21·32·40·48·56·72·96, 섹션 위아래 72·104·144. 콘텐츠 최대 폭 1024px, 카드 간격 20px.
- 반경: 8·12·16·24와 알약. 마케팅 카드 16, 큰 CTA 16~24, 제품 컨트롤 6~8.
- 그림자: 팝오버 `0 0 0 1px rgb(0 0 0/.03), 0 10px 14px rgb(0 0 0/.06), 0 14px 32px rgb(0 0 0/.12)`, 대화상자 `0 0 0 1px rgb(0 0 0/.04), 0 24px 72px rgb(36 42 48/.22)`.

## 페이지 틀

서비스 페이지는 아래 순서를 거의 바꾸지 않습니다. 새 기능 페이지도 같은 순서로 시작합니다.

1. 69px 고정 검은 헤더. 영문 메뉴 6개, 오른쪽에 테두리 버튼 "로그인"과 흰 버튼 "도입 문의하기".
2. 어두운 히어로. 52px 제목, 17px/600 한 줄 설명, 테마 색 주 버튼(68px, 반경 16)과 흰 12% 보조 버튼.
3. 같은 어두운 바탕에 번호 원(32px)이 붙은 기능 바로가기 4~5개. 각 항목은 아래 섹션 id로 이동합니다.
4. 흰 기능 섹션 반복. 왼쪽 정렬 두 줄 제목(36px/700) → 짧은 설명 → 하위 기능(H3) → #f5f5f7 틀 속 제품 화면.
5. 섹션 사이 회색 인용 띠. 첫 문장만 진하게, 출처는 굵은 회사·이름과 옅은 직함.
6. "이런 것도 있어요" 아이콘 격자 → FAQ 아코디언 → 관련 서비스 카드 2장.
7. 검은 푸터. 슬로건, 회색 보조 버튼, 80px 초록 주 버튼, 작은 회색 분류명 아래 링크 열.

테마 페이지는 2번 대신 심볼 + 영문 테마명 + 1000px 높이 히어로, 3번 대신 "왜 제대로 되지 못할까요?" 문제 카드 계단을 둡니다.
홈과 About은 영상처럼 한 화면씩 넘기는 이야기 구조입니다: 그레인 그라데이션 히어로 → 로고 흐름 띠 → 큰 인용 질문 → 스크롤로 밝아지는 문단 → 번호 단계마다 겹친 제품 카드.

## 컴포넌트 규칙

- 버튼: 헤더 34px(반경 8), 히어로 68px(반경 16, 좌우 28), 푸터 80px(반경 24, 좌우 44). 글자는 13~17px/700. 화살표 "→"는 주 버튼에만 붙입니다.
- 메가 메뉴: 헤더 아래 전체 폭 패널. 왼쪽에 24px 큰 분류, 오른쪽에 11px 분류명 + 14px 링크 열. 열리면 본문을 흐리게 합니다.
- 문제 카드: 번호 원 + 굵은 15px 문장. 짝수 카드를 24px 내려 계단을 만듭니다. 카드 바탕은 #262627.
- 세 기둥 카드: 흰색 4% 바탕, 흰색 8% 테두리, 선 아이콘과 긴 설명만. 제목을 넣지 않습니다.
- AI 답변 카드: 어두운 유리 카드 두 장을 엇갈려 겹칩니다. 질문은 오른쪽 위 초록 알약, 답은 요약 한 문장 + 근거 한 문장 + 진행 막대. 기준 미달은 주황 배지.
- 제품 표: 44px 행, 12px 회색 머리글, 들여쓰기로 상하위 목표 표현, 마감은 회색 태그, 진행은 4px 막대 + 숫자.
- FAQ: 1024px 폭, 질문 17px/600, 오른쪽 +. 열리면 질문 줄이 #f5f5f5 둥근 바탕이 되고 +가 45도 돌아 ×가 됩니다. 여러 개를 함께 열 수 있습니다.
- 블로그: 33px 알약 칩(선택 시 검정), 사진 대신 문장형 썸네일. 핵심어 하나에 형광 마커(orange, green, purple, lime)를 칠하고 밝은·검은 썸네일을 번갈아 둡니다.
- 가입: 340px 폭 카드, 초록→청록 그라데이션 제목과 버튼, 아이콘이 붙은 44px 입력. 오류는 위험색으로 입력 아래에.

## 제품 UI 컴포넌트

구성원·조직 관리 소개 페이지의 제품 캡쳐 18장에서 유추했습니다. 실행 예제는 [제품 UI 연구](../../assets/extended/index.html#product-ui)에 있습니다.

- 공통: 흰 바탕, 13px 본문, 잉크 #242a30, 라벨 #96999c. 값 앞에 회색 라벨을 붙이는 "라벨 값 라벨 값" 한 줄 표기를 표 대신 씁니다.
- 측정한 색: 제품 초록 #0ab818(버튼·체크·진행 알약), 승인 대기 노랑 #f9b000, 조건 항목 갈색 #845000, 조건 알약 파랑 #1f78d1과 테두리 #96c6ea, 요청 정보 청록 #12b8a6, 지난 마감·필수 점 #f44712, 선택 행 #f6f6f7.
- 아이콘: 1.6px 선 아이콘(16px)만 씁니다. 글자 기호나 이모지로 대신하지 않습니다. 행 머리 아이콘은 #cacccd, 동작 아이콘은 #61666a입니다.
- 아바타: 반경 34%의 둥근 사각형. 사진이 없으면 이니셜과 옅은 색 바탕을 씁니다. 여러 명은 -6px로 겹치고 "외 N명"으로 줄입니다. 대상이 아닌 사람은 흑백과 45% 불투명도로 흐립니다.
- 선택 컨트롤: 22px 둥근 사각 체크박스와 원형 라디오. 선택되면 초록으로 채우고 흰 체크·점을 그립니다.
- 작은 태그: 18px 높이, 반경 6, 회색 테두리("조직장", "3년 2개월"). 재직 기간처럼 눈에 띄어야 하는 값만 옅은 노랑을 씁니다.
- 프로필 시트: 커버(오른쪽 위 전체 화면·닫기, 아래 "커버 편집"), 96px 아바타, 탭 9개와 "정보 변경 내역", 회색 띠 섹션 머리(기준 기간 · 변경 / + 추가), 50px 아이콘 행, 민감한 값은 점으로 가림, 긴 값은 줄임표와 오른쪽 화살표. 오른쪽 272px 패널에 소개·연락처·근무 시간·연차·"다음으로 이동" 칩. 성장 탭은 작성 입력, 기간 칩, 프로젝트 카드(파일 칩·이미지 격자·스킬 칩)와 언어 수준·자격증 패널로 바뀝니다.
- 조직도: 이름·인원·조직장(노랑 별)과 ···만 담은 232px 카드. 카드 아래 걸친 하위 조직 수 알약은 펼침 초록 ▴, 접힘 회색 ▾. 둥근 모서리(14px)의 회색 선으로 잇고, 오른쪽에 트렌드·조직뷰·조직설정 세로 툴바를 띄웁니다.
- 저장된 보기: 바로 고치는 제목과 설명, 파란 테두리 조건 알약(아이콘 · 항목 · 값 · ×), 검색·정렬과 필터 사이 세로선, 초록 "보기 저장".
- 조건 빌더: "항목 ▾ · 값 ▾ · 이면서"를 문장처럼 잇고, 항목은 갈색 굵은 글자, 묶음 사이는 "또는" 알약.
- 승인 흐름: 노랑 "승인필요" 배지와 오른쪽 위 사이드바·닫기, "이전 값 → 새 값" 비교 상자(이전 값은 회색), 연필·체크 아이콘이 붙은 활동 기록, 빨간 ×의 넓은 취소 버튼. 오른쪽은 참조 → 단계별 승인자이며 진행 단계만 초록 제목, 대기 단계는 사람까지 45%로 흐립니다. 한 단계의 승인자가 모두 승인하면 다음 단계가 켜집니다.
- 모바일 서류 제출: "관련 서류 제출"과 분홍 "입력 필요" 배지. 회색 둥근 행에 클립(미제출)·초록 체크(제출됨), 제출된 행에만 다운로드 아이콘.
- 상태 알약: 진행중(옅은 초록), 요청 전(회색 채움), 완료(테두리만). 지난 마감일은 위험색으로 씁니다.
- 필수 토글: 서류를 체크해야 "필수" 알약이 활성화되고, 켜진 필수는 초록으로 채웁니다.
- 신청 양식: 필수 빨간 점, 두 열 체크·라디오, ? 도움말, 글자 수 표시 비고, 초록→청록 그라데이션 버튼.

## 움직임

- 열림·이동: cubic-bezier(.16, 1, .3, 1), 180~240ms. 등장은 opacity 0→1과 scale .98→1. 닫힘은 scale .99로 살짝만 줄입니다.
- 펼침 높이: grid-template-rows 0fr→1fr, 200ms ease-out. 아이콘 회전은 180ms.
- 호버: 색만 150ms에 바꿉니다. 크기를 키우지 않습니다.
- 프롬프트 입력: 한 글자씩 입력하고 1.8초 뒤 지우는 반복. 로고 띠는 일정 속도로 흐르고 양 끝을 바탕색으로 지웁니다.
- 스크롤 문단: 화면 가운데를 지나는 묶음만 밝힙니다. 동작 감소 설정에서는 모든 움직임을 멈추고 최종 상태를 보여 줍니다.

## 문장 톤

- 해요체로 친근하게 씁니다: "가능하답니다", "확인하세요", "시작해 보세요".
- 문제는 질문으로 엽니다: "왜 제대로 되지 못할까요?", "시간을 많이 쓰고 계신가요?" 답은 다음 섹션 제목이 맡습니다.
- 제목은 결과를 말합니다: "학습이 필요 없는 직관적인 근무 입력", "법이 자동으로 지켜지는 운영". 기능 이름만 나열하지 않습니다.
- 한 문장에 강조색 단어는 하나입니다: "조직을 **제대로** 아는".
- 내비게이션과 슬로건은 영어, 본문과 버튼은 한국어로 씁니다.

## 옮길 때 확인

- 강조색을 프로젝트 색으로 바꿔도 어두운 바탕 대비 4.5:1 이상인지 확인합니다. 형광 초록 위 글자는 #111을 씁니다.
- 흰색 48% 이하 글자는 보조 정보에만 씁니다. 본문 문장에 쓰면 대비가 부족합니다.
- 고정 헤더가 있으면 기능 바로가기 대상에 scroll-margin-top을 69px 이상 줍니다.
- 문장형 썸네일과 마커는 실제 글 제목과 같은 문장을 씁니다. 썸네일만 다른 말을 하면 화면 읽기 도구 사용자가 혼란스럽습니다.
