# 이미지로 먼저 디자인하기

[스킬 본문](../SKILL.md)으로 돌아갑니다. 이미지로 배치·비율·여백·색의 관계를 잡은 뒤 실제 반응형 코드로 옮깁니다.
그림의 완성도와 실제 업무 기능은 따로 확인합니다.

## 언제 그림을 먼저 만들지

새 화면, 여러 디자인 방향, 전체 다시 만들기에서 이미지 도구가 있으면 활용할 수 있습니다.
환경의 이미지 도구를 먼저 봅니다. 쓸 수 없다면 키를 요구하거나 멈추지 않고 코드로 진행합니다.

사용자가 방법을 아직 고르지 않았다면 추천 방향 설명과 함께 한 번만 묻습니다.
그림을 만들고 코드까지 이어 하기, 그림 없이 코드부터 하기, 그림만 받기를 구분합니다.
이미 바로 하라고 했거나 방법을 정했다면 같은 결정을 다시 묻지 않습니다.
유료 서비스는 이번 작업에서 허용한 경우에만 사용합니다.

## 참고의 범위와 코드의 몫

스타일을 배우는 것, 메뉴와 틀만 남기는 것, 정확히 따라 만드는 것을 나눕니다.
기존 틀을 남기거나 그림을 고칠 때는 실제 캡처를 `--ref`에 넣고 고정할 곳과 바꿀 곳을 적습니다.
그림을 실제로 전달하지 않았다면 말로 정리한 참고라고만 부릅니다.
그대로 따라 만드는 작업은 전체 그림으로 측정하고, 일부 그림을 다시 그릴 필요가 있을 때만 이미지 도구에 보냅니다.
글·레이아웃·버튼·아이콘·차트는 실제 HTML/CSS로 만듭니다. 사진·그림·특수 브랜드 이미지는 따로 둡니다.
좋은 원본과 프로젝트 자료를 먼저 쓰고, 로고를 기본적으로 다시 그리지 않습니다.

## 요청 문장 쓰기

사용자가 보고 다루는 순서를 먼저 정합니다. 소개 화면은 중심 그림과 글, 도구는 주된 판단과 동작, 모바일은 내용과 버튼의 비율,
게임은 세계관과 실제 입력의 읽기 쉬움을 먼저 봅니다.
표와 목록이 맞는 곳에 쓸 수 있지만 사이드바·수치 카드·꺾은선·표를 모든 제품의 답으로 삼지 않습니다.
비대칭·어긋남·겹침·특수 자르기는 목적과 작은 화면의 처리 방법을 설명할 수 있을 때 씁니다.

CSS 화면 크기, 문서 높이, 이미지 픽셀 수를 따로 적습니다.
390×844용 그림을 1024×1536으로 만들더라도 1024를 모바일 배치 너비로 쓰지 않습니다.

이미지 요청은 보통 영어 45~65단어, 2~3문장으로 구조 관계·비율·여백·색의 역할·그림 요소에 집중합니다.
여러 실제 제목과 숫자를 모두 그리게 하면 글자와 상자 크기가 틀어질 수 있습니다.
그림 단계에서는 제품 분야와 한국어 화면이라는 조건, 일반 아이콘과 외부 로고 금지를 적고 실제 문구는 코드에서 씁니다.
작은 비율의 도구와 충분한 여백을 요청하되, 큰 글자가 중심인 방향까지 일괄 금지하지는 않습니다.
기존 프로젝트의 실제 바탕·주색·보조색을 먼저 유지합니다.
새 도구 화면의 색 출발점으로는 80~85% 중립 바탕, 10~15% 낮은 밝기의 중심 면, 약 5%의 핵심 강조를 쓸 수 있습니다.
메뉴·주된 버튼·모든 그래프를 똑같은 쨍한 색으로 칠하지 않습니다. 중심이 아닌 수치는 중립색으로 물러나게 합니다.
실제 데이터 관계를 설명하는 그래프 요소 2~3개를 고르고, 빈 큰 표와 가는 선만으로 채우지 않습니다.

아래 다섯 자리를 제품에 맞게 채웁니다. 한 색과 컴포넌트 조합을 모든 제품에 강제하지 않습니다.

```text
<Tone and page role> UI design (<output dimensions>), Korean interface for <product domain>.
<Canvas and existing color roles> with <navigation and content structure>, anchored by <one focal region and restrained highlights>,
featuring <two or three relevant visual elements>, clean abstract icons, no third-party brand logos.
```

첫 자리는 도구·개발 화면·브랜드 첫 화면·전체 소개 화면·독립 컴포넌트 중 실제 역할을 씁니다.
둘째 자리는 밝거나 어두운 중립 바탕과 기존 토큰을, 셋째 자리는 실제 읽는 순서와 구조를 적습니다.
넷째 자리는 어두운 중심 카드·별도 도구 패널·긴 화면의 중심 블록과 작은 강조를, 다섯째 자리는 해당 작업의 수치·단계·실물·도식을 고릅니다.
다른 브랜드나 매체 이름을 쌓기보다 그 표현 방식이 무엇을 돕는지 적습니다.
글꼴 참고는 모양·두께·비율·간격으로 풀고 외국어 글꼴 분류를 한국어 글꼴과 단순 대응하지 않습니다.
기존 화면을 바꾸면 보존할 메뉴·작은 도구 비율·색을 먼저 적고, 바꿀 영역과 새 내용으로 이어 씁니다.
그림 한 장에 숨어 있는 모든 상태까지 넣으려고 하지 않습니다.

## 전체 소개 페이지

세로 1024×1536은 넓은 웹페이지의 위에서 아래까지를 보여 주는 그림일 수 있습니다.
모바일 앱이나 한 장의 포스터로 오해되지 않게 적습니다.
첫 장면은 [소개 화면의 첫 장면](direction-persuasion.md)에서 고릅니다.
위쪽 메뉴·주된 장면, 다른 형태의 이야기, 테두리 없는 세부 설명이나 실제 제품, 고유한 마지막 버튼과 푸터처럼 서로 다른 네 구간을 정합니다.
한 장에 읽을 수 있게 담기면 전체를 만들고, 너무 길어 작아지면 구간 경계에서 나눕니다.
첫 구간을 실제로 확인한 뒤 같은 규칙과 `--ref`를 다음 구간에 쓰고, 이음새의 메뉴·제목을 거듭 넣지 않습니다.

## 코드로 옮기기

실제 이미지를 열어 목표 CSS 크기에서 범위·배치·읽기 쉬움·만들 수 있는지를 봅니다.
매번 큰 문제 하나, 남길 특징, 바꿀 값을 적습니다. 빛 번짐과 질감을 만능 보완책으로 쓰지 않습니다.
완성 이미지를 페이지 배경 한 장으로 쓰거나 `position: absolute`를 남발해 모든 픽셀을 고정하지 않습니다.
이미지는 스타일·색·큰 배치의 기준입니다. 압축된 세로 여백과 깨진 작은 글자는 그대로 베끼지 않습니다.

```bash
python3 <skill>/scripts/measure_reference.py design.png --color bg=20,20,100,40 --box main=40,120,960,640 --css-width 1440
```

`--color`로 색, `--box`로 가로 비율을 보고, 실제로 필요한 사진·그림만 `--extract`로 뽑습니다.
`--white-to-alpha`와 `--key-color`는 필요한 경우에만 씁니다.
긴 그림은 4~6개 구간을 담느라 실제 여백의 1/3~1/2로 눌렸을 수 있습니다.
소개 화면은 첫 높이 `min-height: clamp(640px, 82vh, 880px)`, 블록 간격 `padding-block: clamp(88px, 9vw, 136px)`,
제목과 내용 40~64px를 출발점으로 실제 읽기 크기를 맞춥니다. 넓은 화면 1440px에서 전체 높이 3200~4800px가 될 수 있습니다.
도구는 바깥 창 장식을 빼고 주 공간 사이 20~28px, 카드 안 22~28px, 행 높이 44~56px부터 봅니다.
기존 프로젝트는 현재 라우트·컴포넌트·토큰을 먼저 쓰고 이미지 때문에 전체 도구를 다시 만들지 않습니다.
깨진 글자와 임시 문구는 자연스러운 한국어로 고칩니다. 실제로 쓰는 `VCO`, `AUV`, `HRV`, `USD` 같은 표준 약어는 유지합니다.
마지막에 [도구](tools.md)로 넓은 화면과 작은 화면을 직접 보고, 긴 글·늘어난 목록·핵심 경로를 실행합니다.
