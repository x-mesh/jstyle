# 움직임

## 먼저 갖출 세 가지

새 화면이나 흐름을 바꾼 화면에는 주된 버튼의 즉각적인 반응, 상태가 바뀌는 과정 하나, 첫 진입 때 한 번의 등장을 만듭니다.
예를 들어 버튼은 눌린 모습을 바로 보여 주고, 펼친 곳은 누른 자리에서 이어지며, 처음에는 주인공이 먼저 보입니다.
그 밖의 움직임은 반응·안내·이어짐·브랜드 표현 중 맡은 일이 있을 때만 더합니다.
단순한 상태 변화는 CSS나 기존 컴포넌트, 드래그와 여러 대상의 움직임은 이미 쓰는 모션 도구를 먼저 고릅니다.
영상으로 미리 정한 장면을 보여 줄 수는 있어도 실제 버튼이나 실시간 데이터를 대신하지 않습니다.
스크롤이나 드래그가 장면을 이끌 때는 입력을 되돌리거나 빠르게 움직여도 따라와야 합니다.

## 움직이는 느낌

디자인의 재질과 분위기에서 속도와 무게를 정합니다. 자주 누르는 동작은 짧고, 드문 브랜드 장면은 조금 길어도 됩니다.

- 딸깍 붙기: 자석이나 걸쇠. spring stiffness 350~400, damping 10~15. 작은 버튼과 스위치에 알맞습니다.
- 미끄러져 들어오기: 공기압 문이나 서랍. 250~300 / 20~25. 패널과 접기에 씁니다.
- 천천히 흐르기: 꿀이나 안개. 150~200 / 30~40. 장면의 중심 그림에 씁니다.
- 무게 있게 닿기: 망치나 돌. 400~500 / 5~10. 작고 분명한 끝맺음에 씁니다.
- 튕기기: 고무공. 300 / 8. 축하나 놀이의 작은 물체에 씁니다.
- 떠 있기: 풍선이나 부유물. 100 / 25. 꿈같은 장면에 제한해서 씁니다.

큰 패널이 도착점을 넘기는 폭은 1~2% 이내로 둡니다. 작은 배지나 체크는 10~20%까지 쓸 수 있습니다.
낮은 damping은 작은 물체에만 씁니다. 전체 화면을 크게 흔들지 않습니다.
일부러 거친 스타일이면 80~150ms의 선형 전환이나 끊어 보이기도 쓸 수 있습니다. 이유 없이 기본 easing을 쓰지 않습니다.
spring을 CSS `linear()`로 옮기면 20~30개 지점을 쓰고, 끝점의 0.5% 안에 머무는 때를 길이로 정합니다.
지원하지 않는 브라우저에는 가까운 `cubic-bezier`를 둡니다.

## 하나의 동작으로 이어 주기

사용자가 누른 곳에서 변화가 시작되게 합니다. 담은 물건이 가방으로 이어지고, 숫자도 그 뒤에 바뀌는 식입니다.
한 번의 전환에서는 제목·표시·배경의 이동 방향을 맞춥니다.
주인공이 먼저 움직이고 관련 대상은 40~80ms 뒤에 더 작게 따라오게 할 수 있습니다.
버튼이 패널로 펼쳐지는 것처럼 같은 대상임을 알아볼 수 있게 합니다.
화면에 한두 곳만 기억에 남는 움직임을 만들고 나머지는 조용히 받칩니다.
제품에서만 성립하는 동작을 찾지 못하면 기본 세 가지부터 제대로 만듭니다.

## 상태와 화면 사이

목록에서 상세로 갈 때는 고른 항목이 다음 화면의 주인공으로 이어집니다. 돌아오면 원래 자리와 스크롤을 되찾습니다.
원래 자리가 화면 밖이면 먼저 보이는 곳으로 옮깁니다.
옆 패널은 놓인 쪽에서 들어오며 닫힐 때도 같은 길로 돌아갑니다.
같은 내용의 크기나 위치만 바뀌면 새것과 옛것을 겹쳐 흐리게 하지 않습니다. 바깥 모양을 바꾸고 내용은 바로 보여 줍니다.
내용 자체가 달라질 때만 교차 페이드를 씁니다.
사라지는 것, 새로 생기는 것, 남아 자리를 옮기는 것을 나눠 처리합니다. 목록 전체를 한꺼번에 깜빡이지 않습니다.
탭이나 분할 버튼의 선택 표시는 한 덩어리가 이동하게 하고 너비도 함께 맞춥니다.
첫 표시·화면 크기 변경·글꼴 로딩 뒤에는 표시를 바로 제자리에 둡니다.
이미지와 다음 화면을 먼저 준비해 움직임 끝에 빈 화면이 남지 않게 합니다.
나가는 시간은 들어오는 시간의 약 60~70%로 짧게 합니다.
첫 항목이나 마지막 항목에서 더 갈 수 없으면 10~15px 정도의 작은 반응으로 끝을 알릴 수 있습니다.

## 전체 페이지 전환

덮개가 지나가는 방식은 서로 다른 두 페이지에도 안정적으로 쓰기 쉽습니다.
두 페이지를 겹쳐 두는 방식은 동시에 남는 DOM과 메모리를 다뤄야 합니다.
같은 대상을 두 화면에 잇는 방식은 연속성이 좋지만 빠른 두 번 누르기·뒤로 가기·크기 변경에서 틀어질 수 있습니다.
그 경우 최종 상태를 바로 보여 주는 경로를 마련합니다.
큰 파일을 기다릴 때만 첫 로딩 장면을 두고, 보통 화면 이동을 긴 연출로 막지 않습니다.

## 길이와 크기

버튼·스위치·선택 표시는 150~300ms, 눌림 반응은 약 80ms부터 바로 보입니다. 눌렀을 때 크기는 0.96~0.98 정도입니다.
팝오버는 180~250ms, 패널·서랍은 250~400ms, 전체 화면은 350~500ms부터 시작합니다.
첫 등장은 40~80ms 간격으로 이어지고 전체가 600ms를 넘지 않게 합니다. 상태 갱신마다 거듭 재생하지 않습니다.
hover 이동은 보통 2~4px입니다. 20px가 넘는 이동은 가볍게 떠다니는 느낌을 줄 수 있습니다.
게임 연출의 길이는 [게임](play.md) 규칙을 따릅니다.

복사·저장처럼 눈에 안 보이는 결과는 실제 끝난 일을 말하는 짧은 알림으로 알려 줍니다.
계속 눌러도 같은 축하 동작을 거듭 재생하지 않습니다.

## 실행과 확인

상태는 즉시 바꾸고 움직임이 끝나기를 기다리지 않습니다.
빠르게 다시 누르면 지금 위치에서 이어져야 합니다. 자주 바뀌는 동작에는 CSS transition이 알맞습니다.
반복 애니메이션은 가능하면 transform과 opacity를 바꿉니다. 읽기·쓰기 작업을 프레임마다 뒤섞지 않습니다.
화면 밖, 숨긴 탭, 할 일이 없을 때는 멈추며 이벤트와 루프를 치웁니다.
동작 감소 설정에서는 모든 내용이 바로 보이며 주요 작업을 막지 않아야 합니다.
직접 정상 속도로 다루고, 되돌리고, 빠르게 여러 번 눌러 봅니다.
측정하지 않은 프레임률이나 성능 향상을 보고하지 않습니다.

View Transition의 이름은 같은 시점에 하나뿐이어야 합니다.
모양만 바꿀 때는 이전 스냅샷을 숨겨 겹침을 막습니다. 전환 pseudo-element 뒤에 쓸 수 없는 `:not(...)`을 붙이지 않습니다.
필요하면 루트 속성으로 장면을 나눕니다. iframe과 이미지가 준비되기 전에 전환을 시작하지 않습니다.
