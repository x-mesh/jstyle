# 게임과 손으로 다루는 화면

미니게임, 추첨, 뽑기, 시간에 따라 자라는 화면, 다이얼·레버·조이스틱처럼 다루는 과정이 재미인 작업에 적용합니다.

## 먼저 적을 것

참고 화면이나 그림을 고르기 전에 사용자가 다루는 물건을 적습니다.
각 물건마다 알아보는 특징, 주된 동작이 바꾸는 부분, 필요한 상태, 눈에 보이는 반응, 그림과 그리기 비용을 적습니다.
시작·조작 가능·입력 또는 연출 중·잠김·결과·실패·다시 시작을 실제 게임 규칙에 맞게 고릅니다.
같은 정지 그림에 문구만 바꿔 여러 상태를 만든 것처럼 보이지 않게 합니다.

`주된 동작 → 물건의 변화 → 보이는 반응 → 다음 동작 또는 결과`를 한 줄로 적습니다.
화면마다 주인공 하나와 주된 동작 하나를 정합니다. 입력 방법과 반응이 나타나는 곳도 적습니다.
터치와 마우스의 차이가 있을 때만 둘을 따로 설명합니다.
물건·상태·반응이 빠졌거나 핵심 흐름을 실행할 수 없으면 그림을 만들기 전에 다시 정리합니다.

## 과정이 곧 놀이

회전판 셋이 차례로 멈추는 연출은 약 2초여도 됩니다. 일반 화면의 500ms 기준으로 억지로 줄이지 않습니다.
돈을 썼거나 결과가 정해지면 알맞은 시점에 저장합니다. 새로고침해도 결과를 잃거나 두 번 결제·지급하지 않아야 합니다.
연출 중 막을 동작을 정합니다. 버튼을 여러 번 눌러도 돈을 거듭 쓰지 않게 합니다.
레버와 다이얼은 누른 자리부터 손을 따라 움직입니다. 정해진 지점을 넘기 전에 놓으면 비용을 쓰지 않습니다.
동작 감소 설정에서도 결과는 같은 규칙으로 정하고 화면만 바로 마지막 모습으로 보입니다.
상태의 변화는 연속 그림으로 살펴봅니다. 감속의 이어짐이나 멈추는 느낌은 직접 다뤄 봅니다.
연속 그림만 보고 실제 속도의 손맛을 확인했다고 말하지 않습니다. 녹화는 [도구](tools.md)의 조건에 맞을 때만 합니다.

## 그림과 공간

필요한 캐릭터·물건·기호·재질을 목록으로 옮깁니다. 자세한 방법은 [이미지와 자료](media.md)를 따릅니다.
SVG와 CSS는 아이콘과 간단한 도형에 씁니다. 손으로 그린 도형을 완성된 캐릭터나 소품 대신 쓰지 않습니다.
쌓기·충돌·밀기·흔들림이나 금속·유리처럼 공간과 물성이 핵심이면 실시간 3D를 고릅니다.
만든 이미지는 텍스처나 스프라이트로 씁니다. 나무 성장과 날씨는 여러 장의 이미지가 더 알맞을 수 있습니다.
실제 장면에 넣은 뒤 빛의 방향, 닿는 곳의 그림자, 옆·뒤·넘어질 때의 모습까지 살펴봅니다.
