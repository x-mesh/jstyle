# 화면과 동작을 살펴보는 기준

만드는 과정에 참여하지 않은 사람이 현재 화면과 동작, 꼭 지킬 조건으로 판단합니다.
파일을 고치거나 다른 점검자를 새로 부르지 않습니다. 눈에 보이는 문제와 개인 취향을 나눕니다.
문제가 없으면 없다고 말하며, 보지 못한 움직임이나 경로를 통과했다고 말하지 않습니다.

## 새 화면과 전체 다시 만들기

같은 종류의 좋은 제품을 기준으로 삼습니다. 애매하면 낮은 쪽 점수를 고릅니다.
다음 하나라도 맞으면 가장 먼저 고칠 문제로 적고, 총점은 7점 이하이며 아직 공개할 수 없다고 밝힙니다.

- 실제 글꼴과 목표 화면의 100% 크기에서 본문을 읽을 수 없습니다.
- 중심 그림이 나중에 바꿀 임시 이미지처럼 보입니다.
- 다른 제품 이름으로 바꾸어도 첫 화면이 그대로 성립합니다. 도구는 주된 업무 관계와 예외가 구분되는지 봅니다. 참고 화면을 그대로 만드는 작업에는 이 항목을 적용하지 않습니다.
- 3초 안에 화면의 주인공이나 주된 동작을 찾을 수 없습니다.

### 먼저 볼 것

첫 화면을 너비 480px, 휴대폰은 180px로 줄여 3초 보고, 글자를 가린 화면도 봅니다.
어느 때의 어떤 제품처럼 보이는지, 가장 먼저 무엇이 보이는지 적습니다.
오래된 일반 템플릿이나 컴포넌트 기본 모양만 보이면 7점을 넘기지 않습니다.
업무 도구가 효율적인 사이드바·표·대기 목록을 쓰는 것 자체는 감점하지 않습니다.
겉모습이 차분히 정돈됐는지, 주된 업무와 예외를 바로 구분할 수 있는지를 봅니다.

서로 다른 방향 셋을 비교할 때는 이름을 가리고 중심 도형·버튼의 표현 방식·주된 동작의 모양을 봅니다.
세 항목이 모두 같으면 색·글꼴·장식만 바꾼 같은 안으로 보고 다시 만들도록 합니다.
같아야 하는 사용자 작업과 내용 자체를 다르다고 요구하지는 않습니다.

제품의 종류를 한 문장으로 쓰고 같은 종류의 좋은 첫 화면과 비교합니다.
원래 관례를 어긴 곳이 알맞은 새 시도인지, 기본 템플릿을 그대로 쓴 것인지 구분합니다.
실제 참고 화면이 있으면 그림·재질·장면의 마감 차이를 나란히 설명합니다.

### 움직임

시간이 표시된 연속 그림이나 실제 조작으로 상태 변화를 봅니다. 정상 속도의 느낌은 직접 조작하거나 재생 가능한 녹화로만 판단합니다.
자료가 부족하면 해당 동작만 더 보고, 모든 상태의 근거를 새로 요구하지 않습니다.
주된 버튼의 반응, 한 상태에서 다음 상태로 이어지는 모습, 처음 들어올 때의 등장부터 봅니다.
소개 화면은 각 블록이 내용에 맞게 나타나는지, 중심 대상이 스크롤에 따라 뚜렷이 바뀌는 장면이 있는지도 봅니다.
모든 곳에서 같은 위로 이동·페이드만 쓰거나 점 하나만 선을 따라 가는 것은 충분하지 않습니다.
게임은 [게임과 손으로 다루는 화면](play.md)의 과정·그림·공간도 봅니다.
움직임을 보지 못했으면 못 봤다고 적고 추측하지 않습니다.

### 더 다듬을 곳

문제를 고친 뒤에도 마감, 디자인의 특징, 움직임을 각각 살펴봅니다.
더하는 것보다 이미 있는 것을 더 좋게 만드는 데 집중합니다.

- 마감: 200%에서 글자·줄 간격, 아이콘 맞춤, 테두리·그림자·상태의 통일을 보고, 100%에서 단어 끊김과 숫자를 봅니다. 화면의 왼쪽 시작점은 보통 2~3개 맞춤선을 공유합니다. 5~6개로 흩어졌다면 해당 부분을 적습니다.
- 디자인의 특징: 작게 줄여도 주인공이 보이는지, 기본 컴포넌트 모양에 머문 곳이 있는지 봅니다. 같은 배치가 연달아 두 번 또는 전체에서 세 번 되풀이되면 지적합니다. 모든 내용을 상자에 넣거나 첫 화면 뒤부터 기본 가로줄·입력창만 이어 놓는 것도 봅니다.
- 움직임: 기계적인 등속, 서로 따로 움직이는 대상, 눌렀을 때 이어지지 않는 장면을 적습니다. 필요한 느낌은 동작과 실제 물건의 움직임으로 설명합니다.

쓸모없는 꾸밈 문구, 제작 설명, 임시 자료라는 꼬리표를 찾아 지울 대상을 적습니다.
문구뿐 아니라 합치거나 지울 패널·수치·장식도 적습니다. 지운 뒤 핵심 내용만 빠지거나 뜻이 흐려지면 좋은 수정이 아닙니다.
화면마다 주인공은 하나입니다. 전체 배치·글꼴·이미지·동작이 정한 방향을 뒷받침하는지 봅니다.
도구에서는 첫 줄에 보이는 대상 수와 위치, 현재 대상에서 주된 버튼까지의 거리를 비교합니다.
상세 화면은 표의 값을 되풀이하는 데 그치지 않고 앞뒤 관계를 알려야 합니다.

### 결과를 쓰는 법

먼저 `[문제 1] 위치: 현상 → 고친 뒤 확인할 결과` 형태의 짧은 목록을 줍니다.
문제는 영향이 큰 순서로 최대 5개, 더 다듬을 곳도 최대 5개입니다.
각각 위치·본 근거·영향·바라는 결과·확인 방법을 적습니다. 구체적인 화면 구성이나 데이터 개수를 대신 정하지 않습니다.
첫 화면의 뼈대가 기본 템플릿이고 6점 이하라면 첫 줄에 다시 만들 부분과 까닭을 적습니다. 그 부분의 작은 보완책은 나열하지 않습니다.
끝에서 두 번째 줄에는 꼭 남길 특징 1~2개를 적고, 마지막 줄에는 점수와 다음 단계까지의 차이를 적습니다.
데이터를 잃거나 길이 막히거나 거짓 성공을 보이는 문제는 겉모습보다 먼저 감점합니다.
동작이 된다는 사실만으로 8점을 주지 않습니다.

- 10점: 눈에 보이는 결함이 없고 이 종류에서 보기 드문 좋은 방식이 한 곳 이상 있습니다.
- 9점: 주요 흐름·예외·작은 부분이 잘 이어지며, 한 곳 이상이 같은 종류의 가장 좋은 수준입니다.
- 8점: 방향이 뚜렷하고 작업이 막히거나 자료를 잃지 않습니다. 중심 그림도 좋은 제품 수준이며 작은 화면에서도 특징이 보입니다. 중간 크기 문제는 남을 수 있습니다.
- 7점: 한 곳에서 자료를 잃거나 길이 막히거나, 첫 뼈대가 기본 템플릿이거나, 중심 그림이 임시 도형 수준에 머뭅니다.
- 5~6점: 방향은 보이나 뼈대가 기본 템플릿이거나 주요 경로 여러 곳이 막힙니다.
- 1~4점: 주요 작업을 끝낼 수 없거나 겹침·잘림·읽기 어려움이 있습니다.

점수에는 구체적인 차이를 붙입니다. 모델이 다른 점수를 직접 비교하지 않으며 사용자의 판단을 우선합니다.
존재를 확인하지 않은 파일과 줄 번호를 만들지 않습니다.

## 기존 화면 다듬기

이상적인 새 스타일을 가정하지 않고 실제 프로젝트의 규칙을 따릅니다. 이 방식에서는 점수를 매기지 않습니다.
문서가 없으면 기존 토큰·컴포넌트·같은 종류 화면의 다수 방식을 기준으로 삼습니다.
드문 방식은 맞출 대상으로 남기되, 규칙 자체의 문제는 따로 적어 사용자가 고르게 합니다.
바꿀 수 없는 브랜드·글꼴·주된 색·컴포넌트·메뉴를 먼저 지킵니다.
기존 값 밖의 색·글자 크기·모서리와, 같은 컴포넌트가 있는데 새로 만든 곳을 적습니다.
규칙 안에서 층위·맞춤·여백·덜어내기의 큰 문제 세 곳을 찾습니다.
이번에 바꾼 움직임이 기존 동작을 해치지 않았는지 봅니다. 사용자가 부탁했거나 전체 화면을 바꿨을 때만 전체 움직임을 다시 봅니다.
지울 수 있는 문구도 적되 브랜드 색이나 글꼴을 통째로 바꾸라고 하지 않습니다.
