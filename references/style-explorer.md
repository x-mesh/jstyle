# 디자인 비교 화면

여러 안을 보드에 나란히 놓고 확대·축소하며 비교하고, 하나를 크게 열어 보고 고르는 화면입니다.
비교 도구의 겉모습을 디자인 안의 참고 자료로 삼지 않습니다.
모든 안은 사용자·핵심 내용·주된 동작이 같고, 배치·묶음·글꼴·색·밀도·이미지 방식이 달라야 합니다.
개수는 사용자가 정한 수와 실제로 다른 안의 수를 따릅니다. 같은 제품을 통째로 복사해 수만 채우지 않습니다.

## 입력 파일

한 번에 비교 화면 하나를 만듭니다. 실행 가능한 HTML은 직접 넣고, 프로젝트 안의 실제 페이지는 로컬 URL을 씁니다.
실행할 수 없을 때만 스크린샷을 씁니다. 안마다 대표 화면 하나만 넣습니다. 방향마다 여러 페이지를 함께 볼 때는 아래 matrix를 씁니다.
HTML 파일이 모인 폴더나 여러 HTML 파일을 입력할 수 있습니다. 이름은 `<title>`, 없으면 파일 이름을 씁니다.
같은 폴더의 `manifest.json`을 읽어 설명을 더할 수 있으며, 없어도 만듭니다.

```json
{"candidates": [{"source": "a.html"}, {"source": "b.html"}]}
```

고정 캔버스는 위쪽이나 안별로 `"nativeViewport": "1280x900"`을 둡니다.
직접 만든 움직이는 시안은 `"interactive": true`, 서버 페이지는 `"kind": "url"`과 `url`을 둡니다.
서버 실행 안내는 위쪽 `serve`, 기존 화면은 `"baseline": true`, 스크린샷은 `"kind": "image"`와 `source`를 씁니다.
방향 설명이 있으면 `name`, `concept`, `typography`, `palette`, `traits`도 적습니다. 비운 항목은 보이지 않습니다.
자세한 필드는 `explore --help-build`를 읽습니다.

```text
node <skill>/bin/jstyle.mjs explore <비교할 파일 폴더>
```

여러 HTML이나 manifest도 입력할 수 있습니다. `jstyle` 명령이 설치되어 있으면 `jstyle explore`가 같은 일을 합니다.
기본 출력은 입력 옆의 `style-explorer.html`입니다. 안을 바꿨다면 `--force`로 다시 만듭니다.
결과 JSON 한 줄은 stdout으로 나옵니다. 터미널에서 직접 실행하면 만든 뒤 로컬 서버로 띄워 열고, 에이전트가 실행하면 만들기만 합니다.
사용자에게 보여 줄 때는 만들기, 띄우기, 선택 기다리기를 명령 하나로 합니다. 이 명령을 백그라운드로 실행하고 터미널에 나온 주소를 알립니다.

```text
node <skill>/bin/jstyle.mjs explore <비교할 파일 폴더> --serve --wait
```

`--wait`는 사용자가 안을 고를 때까지 기다렸다가 고른 안을 stdout 마지막 줄에 JSON으로 쓰고 끝납니다. 명령이 끝나면 그 줄로 다음 작업을 이어 갑니다.
이미 만든 비교 화면은 `jstyle serve <결과 파일> --wait`로 띄웁니다. 주소에 붙은 `?t=…`는 고른 안을 보낼 때 쓰는 값이므로 지우지 않고 그대로 알립니다.
휴대폰이나 다른 컴퓨터에서 보려면 `--host 0.0.0.0`을 붙여 띄우고 터미널의 `Other devices` 주소를 알립니다.
그동안 같은 네트워크의 다른 사람도 이 주소를 열 수 있습니다. `kind: url` 안은 이 컴퓨터의 개발 서버를 가리키므로 다른 기기에서는 보이지 않습니다.
생성기가 없으면 안을 직접 볼 수 있게 남기고 비교 화면을 만들지 못했다고 알립니다. 새 도구를 임의로 쓰지 않습니다.
로컬 URL을 쓰면 개발 서버를 켜 둡니다.
나중에 비교 화면을 열어 달라는 부탁을 받으면 `serve.cwd`에서 `serve.command`를 실행하고 `serve.url`의 응답을 기다립니다.

## 페이지 × 방향 보드(matrix)

방향을 처음 정할 때 주요 페이지 2~4개를 함께 봐야 하면 matrix를 씁니다. 한 페이지를 다듬는 회차에는 쓰지 않습니다.
맨 위 `screens`에 페이지 이름을 행 순서대로 적고, 안마다 `screens`에 페이지별 칸을 둡니다.
칸에는 안과 같은 필드(`kind`, `source` 또는 `url`, `interactive`, `nativeViewport`)를 씁니다.

```json
{"screens": ["목록", "상세", "설정"],
 "candidates": [
  {"id": "base", "baseline": true, "name": "지금 화면",
   "screens": {"목록": {"source": "base/list.html"}, "상세": {"source": "base/detail.html"}}},
  {"id": "a", "name": "단정한 표",
   "screens": {"목록": {"source": "a/list.html"}, "상세": {"source": "a/detail.html"}, "설정": {"source": "a/settings.html"}}}]}
```

- 맨 위에 `screens`가 있으면 안 단위의 `source`, `url`, `kind`, `interactive`를 쓰지 않습니다. 화면 필드는 모두 칸에 씁니다.
- 칸은 비워도 됩니다. 빈 칸은 보드에 "이 페이지 없음"으로 보입니다. 안마다 칸이 하나 이상 있어야 합니다.
- 칸에 `nativeViewport`가 없으면 안의 값을, 그것도 없으면 맨 위의 값을 씁니다.
- 페이지는 6개, 칸은 모두 24개, 페이지 이름은 40자까지입니다.

보드는 열이 방향, 행이 페이지입니다. 칸을 누르면 크게 보기로 열립니다. 크게 보기에서 ←/→는 같은 페이지의 다른 방향으로, ↑/↓와 위쪽 페이지 탭은 같은 방향의 다른 페이지로 옮깁니다. 빈 칸은 건너뜁니다.
고르기는 방향 하나를 통째로 고릅니다. 페이지마다 다른 방향을 고를 수는 없습니다. 의견은 칸마다 답니다.
`shoot`은 matrix manifest를 아직 찍지 않고 경고와 함께 건너뜁니다. 칸을 찍으려면 칸의 HTML 파일을 직접 대상으로 줍니다.

## 여러 페이지

여러 페이지를 작업하면 페이지마다 `.jstyle/<페이지>/explore/<회차>/`에 비교 화면을 만들고, 서버는 페이지마다 따로 띄우지 않습니다.

```text
node <skill>/bin/jstyle.mjs hub .jstyle --wait
```

허브는 폴더 아래의 비교 화면을 모두 한 서버로 띄우고, `/<프로젝트>/` 첫 화면에 페이지별 회차 목록과 상태(고름, 의견 수, 검토 전)를 보여 줍니다. 비교 화면 위쪽 막대의 페이지 메뉴로 다른 페이지와 허브를 오갑니다.
`--wait`의 마지막 stdout 줄에는 어느 프로젝트와 비교 화면인지 알려 주는 `project`, `page`가 붙습니다. 허브가 떠 있는 동안 새 비교 화면은 `explore … --no-serve`로 만들기만 하면 허브에 나타납니다.
`--wait` 없이 실행했는데 같은 포트에 허브가 이미 떠 있으면, 새 서버 대신 그 허브에 이 프로젝트를 붙이고 `{hub, project, url}` 한 줄을 stdout에 씁니다. 그 `url`을 알립니다.
고정 포트의 허브는 붙은 프로젝트 목록을 `~/.jstyle/hubs/<주소>-<포트>.json`에 저장합니다. 허브가 끝난 뒤 같은 주소와 같은 포트에서 다시 띄우면 그 프로젝트들이 같은 `/<프로젝트>/` 주소로 돌아오고, 사라진 폴더는 그때 목록에서 빠집니다. `jstyle stop <프로젝트>`로 뺀 프로젝트는 목록에서도 빠집니다.
같은 포트에 허브가 떠 있으면 `--wait`는 서버를 새로 띄우지 않고 그 허브에 프로젝트를 붙인 뒤 대기자로 기다립니다. 그래서 허브의 어느 탭에서 골라도 기다리는 에이전트에게 갑니다. 비교 화면 하나(`serve <파일> --wait`, `explore --serve --wait`)를 기다리면 그 화면의 선택을 받고, `hub --wait`는 그 프로젝트의 어느 화면이든 받습니다. 같은 화면을 기다리는 대기자가 여럿이면 모두 받습니다. 그 화면을 기다리는 대기자가 없을 때만 프로젝트 전체를 기다리는 대기자가 받습니다.
허브 주소의 `?t=…`도 그대로 알립니다.

## 떠 있는 서버

데몬(daemon): 기본 주소(127.0.0.1:8765)로 `hub`, `explore --serve`, 비교 화면 `serve`를 실행하면 떠 있는 데몬이 없을 때 `jstyle daemon`을 분리 실행하고 거기에 프로젝트를 붙입니다. 명령은 주소를 알리고 바로 끝나며, `--wait`는 그 데몬에서 기다립니다. 데몬은 대기자도 열린 화면도 요청도 없이 30분이 지나면 끝나고, 다음 실행이 다시 띄웁니다. 출력은 `~/.jstyle/daemon/daemon.log`에 남습니다. `JSTYLE_NO_DAEMON=1`, 다른 `--port`, loopback이 아닌 `--host`에서는 지금처럼 그 명령이 자기 서버를 띄웁니다. 데몬이 5초 안에 준비되지 않으면 stderr에 이유를 쓰고 빈 포트에 자기 서버를 띄웁니다. `kit`, `library`는 데몬의 `/__skill/` 아래에서 열립니다. `/__skill/`은 두 화면이 링크하는 `assets/`, `references/`, `README.local.md`만 내줍니다. 비교 화면이 아닌 파일의 `serve`는 그 폴더를 데몬 프로젝트로 붙여 엽니다. 이 폴더는 데몬이 떠 있는 동안만 두고 저장 목록에는 넣지 않습니다. `jstyle ps`는 데몬 줄 아래에 프로젝트와 프로젝트마다 기다리는 대기자 수를 보여 줍니다. `jstyle stop <프로젝트>`는 데몬에서 그 프로젝트만 빼고, `jstyle stop 8765`와 `jstyle daemon stop`은 데몬을 끕니다. 대기자가 있거나 데몬이 대기자 수에 답하지 않으면 `--force` 없이는 끄지 않습니다.
버전이 다른 데몬이 떠 있으면 명령이 교체를 요청합니다. 기다리는 대기자가 없으면 옛 데몬이 프로젝트 목록을 남기고 끝나고, 명령이 새 데몬을 띄웁니다. 대기자가 있으면 옛 데몬은 그 대기자들이 끝난 뒤에 스스로 물러납니다. 그동안 명령은 주고받는 방식(`api`)이 같으면 옛 데몬을 쓰고, 다르면 빈 포트에 자기 서버를 띄웁니다. 데몬 이전에 띄운 허브가 127.0.0.1:8765에 떠 있으면 명령이 그 허브를 끄고 같은 토큰과 같은 `/<프로젝트>/` 주소로 데몬을 띄웁니다. 열린 탭은 새로 고치지 않아도 이어집니다. 그 허브에 대기자가 있거나 허브가 `::1`이나 `localhost`에 떠 있으면 끄지 않습니다. 그 허브가 같은 버전이면 그대로 쓰고, 버전이 다르면 빈 포트에 그 명령의 서버를 띄웁니다. 대기자 때문에 늦게 물러난 데몬은 토큰을 포트별 파일 `~/.jstyle/daemon/token-<포트>`(0600)에 남기고, 다음 데몬이 그 토큰을 이어받은 뒤 파일을 지웁니다. 그래서 옛 데몬에서 연 탭도 계속 고르고 보낼 수 있습니다.
서버를 새로 띄우기 전에 `jstyle ps`로 같은 프로젝트의 서버가 이미 떠 있는지 봅니다. 떠 있으면 그 주소를 다시 알리고, 허브라면 새 회차를 `--no-serve`로 만들기만 합니다. 허브에 붙은 프로젝트의 비교 화면을 `serve`나 `explore --serve`로 열면 새 서버 대신 허브의 주소를 알려 줍니다.
보기용 서버는 열린 화면도 요청도 없이 30분이 지나면 스스로 닫힙니다(`--idle`로 조정, `0`은 닫지 않음). `--wait` 서버는 선택을 받거나, 기다리는 프로세스(셸이 아닌 가장 가까운 상위 프로세스, 보통 에이전트)가 끝나면 닫힙니다. 선택 없이 닫히면 stdout이 비고 종료 코드가 1입니다. 허브에서 기다리는 `--wait`도 같습니다. 기다리는 프로세스가 끝나거나 60초 넘게 poll하지 않아 허브가 대기자를 정리하거나, 허브가 꺼지면 stdout이 빈 채 1로 끝납니다.
작업을 마쳤는데 서버가 남아 있으면 `jstyle stop <포트|프로젝트|all>`로 끕니다. 여러 프로젝트가 붙은 허브에서 프로젝트 이름을 주면 그 프로젝트만 빠집니다. 실행 기록은 이 사용자의 모든 세션이 함께 쓰므로 `stop all`은 쓰지 않고, 이 작업이 띄운 포트나 프로젝트만 끕니다.

## 다음 회차

고른 안을 다듬어 다시 비교할 때는 지난 회차를 덮어쓰지 않고 `explore/02/`처럼 회차 폴더를 새로 만듭니다.
새 manifest의 `round`를 `"02"`로 올리고, 지난 회차 폴더와 그 `style-explorer.html`은 고른 기록(`choice.json`)과 함께 남깁니다.
직전 회차에서 고른 안과 나란히 보려면 그 안을 `"baseline": true`로 넣습니다. 비교 화면의 첫 항목이 됩니다.
새 회차에는 사용자가 말한 좋은 점은 유지하고 싫은 점을 바꾼 안만 넣습니다. 사용자가 다시 보자고 하지 않은 방향은 넣지 않습니다.

## 고른 안 기록하기

`--wait`나 `jstyle serve`로 띄운 비교 화면에서는 사용자가 위쪽의 의견 달기(C)를 켜고, 나란히 보기나 한 장 보기의 어느 안에서든 요소를 눌러 의견을 남깁니다.
의견마다 좋음(`keep`)이나 고침(`change`)을 고르고, 오른쪽 검토 패널에서 안별 목록과 전체 의견을 확인한 뒤 보내기나 고르기를 누릅니다.
결과는 비교 화면 옆 `choice.json`에 `round`, `number`(기존 화면은 `baseline`), `name`, `notes`(전체 의견), `comments`, `fingerprint`와 함께 저장되고, `--wait`의 마지막 stdout 줄도 같은 내용입니다.
안을 고르지 않고 보내면 `id`, `number`, `name`이 `null`이고 의견만 담깁니다. 이때는 의견을 반영한 다음 회차를 만들거나, 좋음 의견이 달린 요소들을 한 안으로 합칩니다.
`fingerprint`가 지금 비교 화면의 값과 다르면 다시 만들기 전의 선택이므로 쓰지 않습니다.
의견 달기는 HTML 안에서만 쓸 수 있고, 실행 중인 서버 페이지(`kind: url`)와 이미지 안에는 쓸 수 없습니다.
`comments`의 항목은 안(`id`, `number`, `name`), 성격(`kind`), 의견(`note`), 요소(`element`)로 이루어집니다. matrix 회차에서는 기록 맨 위에 `screens`(페이지 이름 배열)가 붙고, 의견마다 그 칸의 페이지 이름 `screen`이 붙습니다. `element`의 `label`, `path`, `size`, `text`, `parent`, `styles`, `children`은 frame-mesh 채팅이 보내는 선택 요소 요약과 형식이 같습니다.
`path`는 그 안의 HTML에서 `body`부터 내려가는 CSS 선택자이므로, 해당 시안 파일에서 그 요소를 찾아 고칩니다. 의견은 고르지 않은 안에도 달릴 수 있으니 의견마다 `number`를 확인합니다.
검토 패널의 복사는 고른 안, 전체 의견, 요소별 의견(성격·안·요소·위치·글자 일부)을 대화창에 붙여 넣을 글로 복사합니다. 파일로 직접 연 비교 화면에서도 의견을 달 수 있고, 이때는 복사로만 전달됩니다. 서버가 끝난 뒤 보내기가 실패해도 같은 글이 복사됩니다.
사용자가 이 글을 붙여 넣으면 `choice.json`과 같은 방식으로 회차와 번호를 맞춰 봅니다. 의견이 없는 상태에서 고르면 회차·번호·이름만 담긴 한 문장을 복사합니다.
선택을 받으면 지금 manifest의 회차와 번호를 맞춰 보고 설명 문서에 선택과 의견을 적습니다.
비교 화면이 바꾸는 파일은 `choice.json` 하나이며, 에이전트에게 직접 말을 보내지는 않습니다.
마지막에는 아래 명령으로 안의 축소 화면과 `sheet.png`를 한 번에 만듭니다.

```text
node <skill>/scripts/shoot.mjs <manifest 폴더> --size desktop --thumb --out shots/explore
```

각 화면의 페이지·상태·크기가 manifest와 같고 실제 글꼴이 그려졌는지 직접 봅니다.
글자 크기와 작은 부분은 실제 크기 100%로 판단합니다. 창에 맞춰 줄인 그림만 보고 읽기 쉽다고 하지 않습니다.
도구 자체의 동작은 기존 테스트로 확인하며, 매 디자인 작업마다 템플릿을 다시 읽거나 도구를 재검사하지 않습니다.
