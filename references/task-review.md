# 바꾸지 않고 살펴보기

[스킬 본문](../SKILL.md)에서 살펴보기만 부탁한 경우의 흐름입니다.
본 근거·문제의 까닭·제안만 전달하고 제품 파일을 고치거나 새 방향을 만들지 않습니다.

1. 볼 대상, 사용자의 목표, 기기와 꼭 지킬 조건을 적습니다. 관련 화면과 자료만 읽습니다.
2. 실제 실행 화면이나 그림을 확보합니다. 없으면 제한을 알리고 추측을 실제 결과처럼 쓰지 않습니다.
3. [화면을 다른 사람에게 살펴보게 하기](visual-review.md)에 따라 자료를 전달합니다. 독립 실행자가 없으면 직접 봤다고 밝힙니다.
4. 주된 흐름을 확인해야 할 때만 [사용 흐름 점검](ux-review.md)을 더합니다. 겉모습만 보는 일에 흐름 검사를 덧붙이지 않습니다.
5. 영향이 큰 문제부터 위치·관찰·근거·제안을 적습니다. 안을 비교하면 맞는 이유와 비용도 설명합니다.

보고를 마치면 멈춥니다. 제안까지 바로 적용하거나 작업 범위를 늘리지 않습니다.
