# 사용 흐름을 다른 사람에게 살펴보게 하기

새 화면에 폼 제출·여러 단계·저장처럼 주된 흐름이 있거나 사용자가 따로 점검을 부탁했을 때 적용합니다.
작은 겉모습 변경, 첫 화면의 방향 시안, 실제 동작이 없는 화면에는 새 점검자를 부르지 않습니다.
화면의 보기 좋은 정도와 작업 흐름은 따로 살펴봅니다.

점검자는 [사용 흐름 살펴보기](ux-reviewer.md)를 읽습니다. 만드는 사람은 실행 주소, 주로 쓰는 화면 크기, 필요한 테스트 자료와 안전 경계만 전달합니다.
실행 방법의 제약이 있으면 함께 알립니다. 창 크기 자체가 다르다는 이유만으로 문제라 하지 않습니다.
원래 `TASK.md`, 구체적인 사용자 예시, 예상 경로, 소스 코드, 디자인 설명과 지난 문제는 주지 않습니다.

다음 부탁의 경로를 절대 경로로 바꿔 전달합니다.

```text
references/ux-reviewer.md를 읽고 실제 페이지에서 제품과 사용자 목표를 파악하세요.
중요한 작업 하나를 스스로 골라 실행하고, 직접 본 걸림돌을 적어 주세요.
페이지 주소, 주로 쓰는 화면 크기, 필요한 테스트 자료는 다음과 같습니다.
```

실제 조작 도구가 없으면 정지 화면 점검으로 바꾸고, 작업을 끝냈다고 말하지 않습니다.
관찰한 제품의 뜻과 경로는 점검자가 스스로 고른 결과여야 합니다.
점검 기록에 실행한 에이전트 ID나 세션·폴더 식별자, 확인 자료의 위치를 남깁니다.
실행자를 확인할 수 없으면 직접 살펴본 것으로 보고 독립 점검을 마쳤다고 쓰지 않습니다.

받은 문제는 다시 나타나는 제품 문제, 도구·자료 문제, 아직 확인하지 못한 추측으로 나눕니다.
추측이나 도구 문제를 제품 문제로 단정하지 않습니다. 설명만 덧붙여 문제를 덮지 않습니다.
고친 뒤 만드는 사람이 저장·새로고침 후 읽기·실패 복구를 직접 확인합니다.
한 차례 고쳤다고 같은 독립 점검을 다시 요청할 의무는 없습니다.
이 점검은 실제 사용자의 성과나 만족도 측정을 대신하지 않습니다.
