# 화면을 다른 사람에게 살펴보게 하기

점수를 매기는 기준은 [화면 살펴보기 안내](reviewer-manual.md)에 있습니다.
만드는 사람은 기준을 대신 채점하지 않고 현재 자료를 점검자에게 전달합니다.
사용자가 별도 기준을 주었다면 함께 전달하고, 충돌하는 항목은 작업의 기준을 우선합니다.

새 화면이나 전체 다시 만들기는 새 화면 기준으로 1~10점을 받습니다.
기존 화면을 다듬거나 넓히는 작업은 기존 규칙과 비교하며 점수를 매기지 않습니다.
작고 위험이 낮은 부분 변경은 만드는 사람이 직접 봅니다.

## 전달할 것

현재 버전의 스크린샷, 필요한 움직임 자료와 화면 크기, 사용자의 원래 부탁, 바꿀 수 없는 경계를 줍니다.
방향 설명이 있다면 핵심 문장 하나와 꼭 지킬 조건만 전달합니다.
기존 작업은 색·컴포넌트·`DESIGN.md` 등 실제 규칙을 함께 줍니다.
새 화면에서는 브랜드 자산과 하면 안 되는 일만 필요한 만큼 추립니다.
소스 코드, 자신의 선택을 옹호하는 설명, 이전 점수는 주지 않습니다.

자료는 점검자가 열 수 있는 현재 파일이어야 합니다. 바꾸지 않은 상태의 캡처는 다시 써도 됩니다.
긴 화면은 전체 흐름을 볼 수 있게 전달하고, 글을 읽기 어려운 곳만 부분 그림을 덧붙입니다.
부분 그림이 전체 배치를 대신할 수는 없습니다.
움직임은 기존 연속 그림이나 실제 페이지를 전달합니다. 매 상태를 새로 녹화하지 않습니다.
자료로 판단할 수 없을 때만 해당 동작을 더 봅니다.

```text
references/reviewer-manual.md를 읽고 해당 작업 기준으로 현재 화면을 살펴보세요.
전체 배치, 글의 읽기 쉬운 정도와 주된 버튼부터 봅니다.
지금 자료로 판단할 수 있으면 언어·페이지·상태별 캡처를 더 요구하지 마세요.
```

경로는 절대 경로로 바꿉니다. 따로 살펴볼 사람이 없으면 직접 확인했다고 밝힙니다.
실제 화면이 없으면 미적 점수를 주지 않습니다.

## 받은 의견 반영하기

첫 문제가 다시 만들기라면 그 부분의 뼈대부터 고칩니다. 잘못된 뼈대 위에서 작은 부분만 다듬지 않습니다.
큰 문제부터 고칩니다. 남겨야 할 특징도 기록해 평범하게 바꾸지 않습니다.
너무 빽빽하다는 의견은 간격·글자 크기·그림자의 구체적인 값으로 바꿉니다.
사용자가 고정한 브랜드 색이나 큰 구조를 바꾸라는 제안은 따르지 않는 까닭을 적습니다.
서로 다른 취향만 되풀이하거나 눈에 보이는 이득이 없으면 더 나은 버전을 남기고 멈춥니다.
